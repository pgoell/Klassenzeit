# Klassenzeit backend: rules

Stack: FastAPI + SQLAlchemy async, Alembic, Pydantic. Served under `klassenzeit_backend`. Rules below are on top of `.claude/CLAUDE.md`, not a replacement.

## Layout (`backend/src/`)

- Routes and route handlers live next to the aggregate they serve.
- Runtime state (engine, session factory, settings, rate limiter) lives on `app.state`, set in `lifespan`. No module-level globals.

## Runtime state

- **`app.state` for FastAPI runtime state.** Engine, session factory, settings, and rate limiter live on `app.state` (set in `lifespan`). Tests set these on `app.state` in the `client` fixture. No module-level globals.

## Error handling

- **No bare catchalls.** No bare `except:` / `except Exception` in Python. Catch the specific error you can handle; let the rest propagate.
- **Use `status.HTTP_422_UNPROCESSABLE_CONTENT`** for 422 responses. The older `HTTP_422_UNPROCESSABLE_ENTITY` alias is deprecated in the Starlette/FastAPI stack we pin and raises a `DeprecationWarning` at import.

## Type checking

- **`ty` does not honor `# type: ignore[...]` pragmas.** If `ty` flags a line, silencing it requires the actual type, not a comment. Prefer concrete types (NamedTuple, TypedDict, a tiny dataclass) over returning `dict[str, object]` from helpers that `ty` will traverse.
- **Pre-commit `ty check` blocks a strict "red test with missing module" TDD start.** A test that imports a not-yet-created module fails `ty`'s `unresolved-import` gate, and `ty` has no per-file carve-outs or pragmas. Land a stub module (typed `AsyncSession` signature, body `raise NotImplementedError(...)`) in the red commit; tests still fail at runtime, which is a valid red. Replace the body in the next commit.
- **Don't add `from __future__ import annotations` to test files or backend Pydantic schema modules.** Ruff `TC001/TC002/TC003` then flags every annotation-only import (e.g. `import uuid`, `from collections.abc import Sequence`) as "needs to move into a `TYPE_CHECKING` block." The repo's sibling test/schema files don't use the future import; match them.

## Data access

- **No raw SQL outside the abstraction layer.** All queries go through SQLAlchemy (or whatever repository layer lands later). If raw SQL is unavoidable, it lives inside the data-access module, never in route handlers or business logic.
- **Alembic autogenerate style drift.** `alembic revision --autogenerate` emits `typing.Sequence` and `typing.Union[X, Y]` imports. Repo style is `collections.abc.Sequence` + PEP 604 unions (`X | Y`). Tidy the new revision file before committing; `ruff` does not flag it.
- **Native Postgres `ENUM` columns with a Python `enum.StrEnum` need `values_callable`.** SQLAlchemy 2 sends `member.name` (`GYMNASIUM`) on the wire by default, but the Postgres `CREATE TYPE` carries `member.value` (`Gymnasium`); the round-trip then errors with `psycopg.errors.InvalidTextRepresentation: invalid input value for enum`. Pin the column declaration to `PG_ENUM(SchoolType, name="school_type", create_type=False, native_enum=True, values_callable=lambda enum_cls: [m.value for m in enum_cls])` plus `server_default=SchoolType.<DEFAULT>.value`. The Alembic migration creates the type explicitly with `school_type_enum.create(op.get_bind(), checkfirst=True)` (and `drop(...)` on downgrade); idempotent under the test-template DB cache. Pattern in `db/models/stundentafel.py:Stundentafel.school_type` and `alembic/versions/d89dceb4a06e_add_stundentafel_school_type.py`.
- **`ALTER COLUMN ... TYPE` needs `DROP DEFAULT` first when the existing default has incompatible type.** Postgres rejects the cast otherwise. Canonical shape: `ALTER COLUMN <c> DROP DEFAULT, ALTER COLUMN <c> TYPE <new> USING (<expr>), ALTER COLUMN <c> SET DEFAULT <new-default>, ALTER COLUMN <c> SET NOT NULL` in one `op.execute(...)` per column. The `BOOLEAN → INTEGER` flip in `09dab109a11c_subject_preference_weights.py` is the template; reverse the order for the lossy downgrade.
- **`AsyncSession.execute(delete/update).rowcount`.** `ty` sees the return as `Result[Any]`; `.rowcount` only exists on runtime `CursorResult`. Access it via `int(getattr(result, "rowcount", 0) or 0)`. Pattern in `auth/sessions.py:66-76`.
- **PATCH handlers for nullable columns must use `body.model_fields_set`, not `is not None`.** The default pattern `if body.foo is not None: orm.foo = body.foo` silently drops explicit `null` updates. For nullable FKs and similar fields where clearing is a real intent, gate on `if "foo" in body.model_fields_set: orm.foo = body.foo` so an explicit null clears the column. Keep the `is not None` shape for NOT NULL columns where null has no meaning. Pattern in `scheduling/routes/school_classes.py:update_school_class_route` (`home_room_id` clear path).
- **Routes that mutate DB state must explicitly `await db.commit()` + `await db.refresh(orm_row)` before returning.** The test conftest overrides `get_session` with a savepoint-wrapped shared session, so a missing commit silently passes route tests; production fails because each request gets a fresh `session_factory()` with no caller-side commit, so writes roll back at end-of-request. Sprint C found this latent bug in `POST /api/classes/{id}/schedule`, `POST /api/schedule/all`, and the new `placements.py` endpoints (fix landed in commit `7542d6f`). Templates: `lessons.py` and `rooms.py` (correct from day one).

## Testing

- **Test fixtures, not imports.** `pytest` runs with `--import-mode=importlib`. Shared test helpers must be pytest fixtures (factory pattern) in `conftest.py`, not plain functions imported across test files. Cross-conftest imports break silently.
- **Scheduling entity-aggregate factories** live in `backend/tests/scheduling/conftest.py`: `create_subject`, `create_week_scheme`, `create_time_block`, `create_room`, `create_teacher`, `create_stundentafel`, `create_stundentafel_entry`, `create_school_class`. Join-table rows (`Lesson`, `TeacherQualification`, `TeacherAvailability`, `RoomAvailability`, `RoomSubjectSuitability`) have no factory; construct inline with `db_session.add(...)` + `await db_session.flush()`. `Lesson.preferred_block_size` is NOT NULL with no server default; always set it (typically `1`).
- **`TimeBlock.start_time` / `end_time` are `datetime.time`,** not strings. Pass `time(8, 0)`, not `"08:00"`.
- **`async with db_session.begin_nested():` for tests that expect `IntegrityError`.** The `db_session` fixture wraps every test in an outer nested savepoint; a bare `await db_session.rollback()` in `finally:` escapes the inner savepoint and drops pre-inserted setup rows. Use the `async with` form so the rollback stays scoped. Pattern in `tests/seed/test_demo_grundschule_rollback.py`.
- **Solver sees only `Lesson.teacher_id IS NOT NULL` rows.** `scheduling/solver_io.py:build_problem_json` filters by non-null teacher. `POST /api/classes/{id}/generate-lessons` auto-assigns a qualified teacher per new lesson via `scheduling/teacher_assignment.py:auto_assign_teachers_for_lessons`, so production paths and integration tests that go through the endpoint do not need a manual UPDATE. If a test seeds Lessons directly (e.g. via `db_session.add(Lesson(...))`), pin `teacher_id` inline or the solver returns zero placements with zero violations. Pattern in `tests/seed/test_demo_grundschule_solvability.py`.
- **Greedy-assignment heuristics: sort the input by a stable constraint metric.** `auto_assign_teachers_for_lessons` is the canonical example: it sorts lessons in ascending order of qualified-teacher count (subjects with one qualified teacher first) before walking each lesson's candidate teachers. Pure first-fit on the StundentafelEntry iteration order is non-deterministic across runs because subject UUIDs are random; if a placeholder heuristic in this codebase grows, follow the scarcity-first pattern rather than relying on insertion order.
- **Seed solvability tests drive the HTTP route flow.** There is no public `generate_lessons_for_class` helper; lesson generation lives only inside the `POST /api/classes/{id}/generate-lessons` route handler (auto-commits on its own session). Solvability tests for `demo_*` seeds (`test_demo_*_solvability.py`) seed entities, then call the HTTP endpoint, then `POST /api/classes/{id}/schedule`, then assert on the response. Direct in-process calls to a private helper would skip the auto-assign step the route does.
- **Seed modules import sibling seed modules' `_`-prefixed shared constants.** `demo_grundschule_zweizuegig.py` imports `_PERIODS`, `_SUBJECTS`, `_GRADE_*_HOURS`, `_KLASSENRAUM_SUITABLE_SUBJECTS`, and the NamedTuple types from `demo_grundschule.py` rather than copying them. Cross-module access of `_`-prefixed names is intentional here: the seed package treats these as package-internal shared data; copying would create the cross-fixture drift this PR was designed to prevent.
- **`_TEACHER_ASSIGNMENTS_<NAME>` dicts pin teacher allocation in seed solvability tests.** A `dict[tuple[str, str], str]` mapping `(class_name, subject_short) → teacher_short_code`, owned by the seed module but not consumed by its coroutine; the solvability test runs SQL `UPDATE` after `generate-lessons` to override auto-assign, so the matching Rust bench fixture stays stable as `auto_assign_teachers_for_lessons` evolves.
- **`caplog` records expose `extra=` keys via `record.__dict__[key]`, not `record.key`.** `ty` rejects `record.foo` with `unresolved-attribute` because `LogRecord` has no static schema for `extra=`-injected fields, and `ruff` B009 rejects `getattr(record, "foo")` for static string keys. The working pattern is `record.__dict__["foo"]`. Pattern in `tests/scheduling/test_solver_io.py:test_run_solve_round_trips_and_logs`.
- **Settings tests construct `Settings` directly, not `get_settings()`.** Use `Settings(_env_file=None)  # ty: ignore[missing-argument, unknown-argument]` after the `monkeypatch.setenv("KZ_*", ...)` calls. Avoids the `lru_cache.cache_clear()` dance the obvious template suggests. Pattern in `tests/core/test_settings.py`.
- **Ruff `PLC0415` rejects in-function imports.** Hoist all imports to module top-level even when a test only needs them once. Affects the `monkeypatch.setattr(some_module, ...)` pattern where the obvious move is to import the module inline; import at the top instead.
- **Middleware integration tests use `httpx.ASGITransport(app=build_app(env="dev"))`** + `AsyncClient` + `caplog.set_level(logging.INFO, logger="...")`. Pattern in `tests/test_http_access_middleware.py`. Inline route registration on a built app works: `app = build_app(...); @app.get("/__probe")\nasync def _probe(): ...` is accepted because routes go on `app.router` (not the middleware stack), so a one-off probe endpoint can live inside the test body without mounting the testing router. Used by `test_request_id_propagates_to_route_handler_log` to assert filter-driven enrichment without leaking a "log a line" call site into `/api/health`.
- **Cross-test-module helpers import as `from tests.<module> import ...`,** NOT `from backend.tests.<module> import ...`. There is no `backend/__init__.py`; with `--import-mode=importlib`, the package root is `tests/` (the first ancestor with `__init__.py`). New helper modules under `backend/tests/` (e.g., `_xdist_db.py`) are imported via `from tests._xdist_db import ...` from sibling test files and from `conftest.py`. Note this is for non-fixture helpers (pure functions); fixtures still belong in a `conftest.py` per the rule above.
- **Conftest module-load env mutations need `# noqa: E402` on trailing `klassenzeit_backend` imports.** Ruff E402 tolerates a single trivial statement between imports (the existing `os.environ.setdefault("KZ_ENV", "test")`) but trips on multi-line conditional logic (the per-worker DB suffix block). The `klassenzeit_backend.*` imports must come AFTER the env mutation so `lru_cached get_settings()` lands the right URL; mark each with `# noqa: E402`. Pattern in `backend/tests/conftest.py`.
- **pytest-xdist runs each worker against its own database.** `backend/tests/_xdist_db.py` exposes pure helpers: `worker_database_url`, `ensure_database_exists`. The conftest reads `PYTEST_XDIST_WORKER` (set to `gw0`/`gw1`/... per worker, `master` or unset otherwise), suffixes `KZ_DATABASE_URL` accordingly, and `apply_migrations` calls `ensure_database_exists` to idempotently create the per-worker DB before running alembic. Sequential `mise run test:py` uses `klassenzeit_test` unchanged. ADR 0019.
- **Alembic migrations are cached via a Postgres template database.** `_xdist_db.py` exposes `ensure_template_database`, `clone_database_from_template`, `drop_database_if_exists`. `apply_migrations` opportunistically uses `klassenzeit_test_template` under a `pg_advisory_lock` so only the first worker actually runs alembic; subsequent workers `CREATE DATABASE ... TEMPLATE`. Falls back to per-worker `alembic downgrade base + upgrade head` if the template path raises (locale mismatch, permission, etc.); the fallback logs `template_db.fallback` at WARNING. ADR 0020.
- **Schema-changing PRs: drop the template + per-worker DBs before the first test run.** The conftest's template cache means `klassenzeit_test_template` and any pre-existing `klassenzeit_test_gwN` worker DBs were cloned from the *previous* schema. Running `mise run test:py` against the new branch surfaces as `psycopg.errors.UndefinedTable: relation "<new_table>" does not exist` per worker. Recovery: connect to postgres and `DROP DATABASE IF EXISTS klassenzeit_test_template; DROP DATABASE IF EXISTS klassenzeit_test_gw0; ...` (or just drop everything matching `klassenzeit_test%`). The conftest then re-migrates the template idempotently on the next run. `mise run db:reset` only resets the dev DB, not the template/worker family.
- **`KZ_SOLVE_DEADLINE_MS=0` in `backend/.env.test` makes backend tests greedy-only.** Settings field `solve_deadline_ms: int | None = 200`; the route handler reads it from `app.state.settings.solve_deadline_ms` and threads it into `solver_io.run_solve(..., deadline_ms=...)`. Tests opt out of the 200 ms LAHC wall-clock by default; production keeps the 200 ms LAHC pass.
- **`ViolationResponse.kind` Literal lives in `scheduling/schemas/schedule.py`,** not `api/schemas.py`. Adding a new `ViolationKind` variant to the solver Rust enum requires widening the Pydantic `Literal[...]` union here in lockstep, then `mise run fe:types` to regenerate `frontend/src/lib/api-types.ts`. Two tests in `backend/tests/scheduling/test_solver_io.py` (`test_count_violations_by_kind_clean_solve_returns_zeros` and `test_count_violations_by_kind_aggregates_mixed_kinds`) hardcode the closed-enum kind set and must be updated in the same commit.

## Logging

- **Structured-log events use `logger.info("event.name", extra={...})`.** `core/logging.py:JsonFormatter` merges `extra=` keys into the JSON record at top level via the `_RESERVED` denylist. Reserve `event` as a stable identifier (e.g. `solver.solve.done`, `http.request`); never f-string-interpolate the message. Configured once per process from `build_app` via `configure_logging(env, log_format, log_level)`. JSON is the default in `KZ_ENV=prod`; dev/test stay plain text. ADR 0016.
- **Per-request access log lives on `klassenzeit_backend.http.access`.** The `@app.middleware("http")` handler in `main.py` emits `event=http.request` with `method`, `path`, `status`, `duration_ms`, `request_id`. Inbound `X-Request-ID` is preserved and echoed; absent or oversized (>64 chars) headers regenerate via `_resolve_request_id` from `core/logging.py`.
- **Per-request `request_id` propagates automatically via `request_id_var`** (a `ContextVar[str | None]` in `core/logging.py`). The access middleware sets it after `_resolve_request_id` and resets it in a `finally`. A `RequestIdFilter` on the root stream handler injects the value onto any `LogRecord` emitted inside the request scope that does not already carry `request_id`. Routes do not need to thread `request_id` through `extra=`; explicit `extra={"request_id": "..."}` still wins (e.g. for a background task tagging a follow-up event with the originating request's id). Records emitted outside a request scope (startup, lifespan, non-request asyncio tasks) leave `request_id` absent.
