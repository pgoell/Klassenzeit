# Klassenzeit backend: rules

Stack: FastAPI + SQLAlchemy async, Alembic, Pydantic. Served under `klassenzeit_backend`. On top of `.claude/CLAUDE.md`.

## Layout (`backend/src/`)

Routes and route handlers live next to the aggregate they serve. Runtime state (engine, session factory, settings, rate limiter) lives on `app.state`, set in `lifespan`. No module-level globals.

## Error handling

- **No bare catchalls.** No `except:` / `except Exception`. Catch the specific error; let the rest propagate.
- **Use `status.HTTP_422_UNPROCESSABLE_CONTENT`** for 422 responses (the `_ENTITY` alias is deprecated).

## Type checking

- **`ty` does not honor `# type: ignore[...]` pragmas.** Use concrete types (NamedTuple, TypedDict, dataclass) over `dict[str, object]`.
- **Pre-commit `ty check` blocks a strict "red test with missing module" TDD start.** Land a stub module (typed signature, body `raise NotImplementedError(...)`) in the red commit; replace in the next.
- **Don't add `from __future__ import annotations` to test files or backend Pydantic schema modules.** Ruff `TC001/TC002/TC003` then flags every annotation-only import.
- **Pydantic-settings `env_file=` only injects into BOUND fields.** Declare a scalar field for every env var; `.env.test` values are silently ignored if no matching field exists. Assemble derived views in `@model_validator(mode="after")`, not by reading `os.environ` from a validator.

## Data access

- **No raw SQL outside the abstraction layer.** All queries go through SQLAlchemy.
- **Alembic autogenerate style drift.** Replace `typing.Sequence` with `collections.abc.Sequence` and `typing.Union[X, Y]` with PEP 604 unions in new revisions.
- **Native Postgres `ENUM` columns with a Python `enum.StrEnum` need `values_callable`.** SQLAlchemy 2 sends `member.name` by default; the Postgres `CREATE TYPE` carries `member.value`, the round-trip errors. Pin: `PG_ENUM(MyEnum, name="...", create_type=False, native_enum=True, values_callable=lambda cls: [m.value for m in cls])` plus `server_default=MyEnum.<DEFAULT>.value`. Migration uses explicit `.create(op.get_bind(), checkfirst=True)` and `.drop(...)` on downgrade. See `db/models/stundentafel.py`.
- **`ALTER COLUMN ... TYPE` needs `DROP DEFAULT` first when the existing default has incompatible type.** Canonical shape: `DROP DEFAULT, TYPE <new> USING (<expr>), SET DEFAULT <new>, SET NOT NULL` in one `op.execute(...)` per column.
- **`AsyncSession.execute(delete/update).rowcount`.** `ty` sees `Result[Any]`; access via `int(getattr(result, "rowcount", 0) or 0)`.
- **PATCH for nullable columns uses `body.model_fields_set`,** not `is not None`. Gate on `if "foo" in body.model_fields_set` for nullable FKs so explicit nulls clear the column. Keep `is not None` for NOT NULL columns.
- **`field_validator` methods on multiple Pydantic classes collide with `scripts/check_unique_fns.py`.** Two classes can't both define `_normalize_foo`; suffix per-class (e.g. `_normalize_foo_create` / `_normalize_foo_update`) and delegate to a module-level `_validate_foo` helper for the shared logic.
- **`field_validator` return-type drift trips `ty` at the assignment site.** A validator declared with input `set[int] | None` that returns `list[int] | None` still types the schema field as `set[int] | None`; assigning `body.foo` to a `Mapped[list[int] | None]` column then errors. Workaround: declare the field as the post-validator type so callers see the canonical shape, or convert at the assignment site (`sorted(value) if value is not None else None`).
- **Routes that mutate DB state must explicitly `await db.commit()` + `db.refresh(orm_row)` before returning.** The test conftest's savepoint-wrapped session masks missing commits; production fails because each request gets a fresh session.
- **Migrations that seed reference rows add the seeded table to `testing/router.py:PRESERVED_TABLES`.** The test teardown TRUNCATEs `CASCADE`; without preservation, a FK from another table (`users.school_id -> schools.id`) cascades the truncate up into the seeded row even though the seeded table isn't itself reset. Pattern: `schools` (seeds the default-school row); same shape applies to any future reference-data seed.
- **Adding a NOT NULL FK to a tenanted column on existing tables: transitional `server_default`, then drop in the next commit.** When a new `school_id` NOT NULL FK lands before every writer is wired (e.g. tracer ships schema in commit N; route handlers stamp `current_user.school_id` in commit N+1), set a transient `server_default` matching the canonical default-tenant id (`server_default=text("'00000000-0000-0000-0000-000000000001'::uuid")` on the Mapped column AND `server_default=` on the migration's `add_column`). The follow-up commit removes both server_defaults (model + migration body via `op.alter_column(..., server_default=None)`) once every direct `<Model>(...)` construction in `backend/src/` AND `backend/tests/` (model-level ORM tests bypass scheduling factories and construct directly) stamps the FK explicitly. Leaving the default in past the rewire is a tenant-leakage risk: silently lands rows in the default tenant.
- **Tenant-scoped reads return 404, not 403, on cross-school access.** Route handlers thread `current_user: Annotated[User, Depends(require_admin)]` and scope every query with `.where(<Aggregate>.school_id == current_user.school_id)`. Loader helpers take `school_id` as an explicit parameter and 404 when the row exists in a different school: `async def _get_<thing>(db, thing_id, school_id) -> Thing`. Returning 403 leaks the existence of other-school rows. Create routes stamp `school_id=current_user.school_id` on the new ORM row. Same shape for non-CRUD readers (`_load_room_or_404` in `placements`, `build_problem_json(db, class_id, *, school_id, ...)` in `solver_io`): the school_id rides in as a keyword arg, never inferred from another loaded row. Pattern: `scheduling/routes/rooms.py` (ADR 0045, tracer aggregate). Mechanical for the remaining aggregates under OPEN_THINGS item 10a.
- **Cross-aggregate readers of a tenanted aggregate need the same `school_id ==` filter.** A 10a aggregate's school-scoping is not just its own CRUD: every `select(<Aggregate>)` in a SIBLING-aggregate route or in a domain helper must also filter by `school_id`. Common shapes: `Subject.id.in_(subject_ids)` joins in `solver_io.build_problem_json` and `routes/lessons.py`'s qualified-teacher coverage, single-row lookups by FK id in `routes/stundentafeln.py` and `routes/rooms.py`'s suitability detail / PUT validation, and predicate-by-name helpers like `quality_checks._load_exempt_subjects(db, school_id)` (`Subject.short_name.in_(HOME_ROOM_EXEMPT_SHORT_NAMES) AND Subject.school_id == school_id`). The `school_id` rides in as a kwarg on the helper signature, same shape as `build_problem_json`; never inferred from a sibling-loaded row. Audit `rg -n 'select\(<Aggregate>\)' backend/src/` for the aggregate being scoped and fix every site in the same commit as the route-level rewire. Subject (PR for item 10a) surfaced this fan-out across `routes/rooms.py`, `routes/stundentafeln.py`, `routes/lessons.py`, `solver_io.py`, and `quality_checks.py`; the remaining 10a aggregate (ScheduledLesson) is similarly cross-referenced.
- **Inbound FK fields on a sibling's write path validate against the user's school before stamping.** When a sibling-aggregate POST / PATCH (or any write-shaped route, e.g. `generate_lessons_from_stundentafel`) accepts an FK referencing a tenanted aggregate, the DB-level FK alone does NOT enforce tenancy: the target row exists across all tenants, so a client from school A can supply an FK pointing at a row in school B and the INSERT/UPDATE succeeds. Gate every such write with `select(<Target>.id).where(<Target>.id == body.<fk_id>, <Target>.school_id == current_user.school_id)` and 404 on `scalar_one_or_none() is None` BEFORE stamping. Sites surfaced by the Stundentafel tracer: `routes/school_classes.py` POST + PATCH (`stundentafel_id`), `routes/lessons.py` `generate_lessons_from_stundentafel` (the parent SchoolClass's `stundentafel_id`). The remaining 10a aggregate inherits the same shape (every `lesson_id` / placement FK for the ScheduledLesson tracer). Audit `rg -n '<target_table>_id' backend/src/klassenzeit_backend/scheduling/routes/` for inbound-FK columns when scoping a new aggregate.
- **Per-tenant uniqueness uses composite `UNIQUE(school_id, <col>)`.** Tenanted tables that previously enforced single-column `UNIQUE(name)` or `UNIQUE(short_name)` get a composite `UniqueConstraint("school_id", "name", name="uq_<table>_school_id_name")` (and same for `short_name`) in `__table_args__`; the migration drops the old constraint and creates the composite in one upgrade. Two schools share a namespace via the FK, not via name collisions. Pattern: `db/models/room.py` + migration `4fa6fbc15625_add_school_tenancy.py`. Verify the pre-existing constraint's actual name in the live schema before authoring `op.drop_constraint(...)`: `podman exec klassenzeit-db-1 psql -U klassenzeit -d klassenzeit_dev -c "\d <table>"` and grep for `UNIQUE`. Tables vary between the SQLAlchemy autogen `<table>_<col>_key` shape (when `unique=True` was on the column) and an explicit named constraint like `uq_<table>_<col>` (when a prior migration named it).
- **Tenanted test fixtures default `school_id=DEFAULT_SCHOOL_ID`.** `create_test_user` (root `tests/conftest.py`) and the scheduling factories in `tests/scheduling/conftest.py` accept an optional `school_id: uuid.UUID = DEFAULT_SCHOOL_ID` kwarg; tests exercising cross-tenant behaviour insert a second `School(name=...)` row and pass its id. Import is `from klassenzeit_backend.db.models.school import DEFAULT_SCHOOL_ID`.
- **Tenancy-test second-school fixture name must encode the aggregate.** Per-aggregate tenancy test files (`test_<aggregate>_tenancy.py`) each define a `school_b`-shaped fixture for the second tenant; `scripts/check_unique_fns.py` blocks any name collision across the test tree. Name the fixture after the aggregate (e.g. `school_b_classes` in `test_school_class_tenancy.py`, `school_b` in `test_room_tenancy.py`, `school_b_lessons` in `test_lesson_tenancy.py`). The same rule will trip the next 10a aggregate PRs in sequence; mirror the local convention each time.
- **Tenancy tracer PRs are load-bearing on `mise run fe:types` even without Pydantic schema changes.** The `_admin` → `current_user` parameter rename plus the route-docstring rewrites ("scopes the lookup to their school", "stamps `school_id` from the current user") propagate through FastAPI's OpenAPI generator into `frontend/src/lib/api-types.ts` as JSDoc / `@description` text. The diff is text-only (zero schema-shape change), but `git status frontend/src/lib/api-types.ts` is dirty after the route rewire. Regen via `mise run fe:types` and commit the result alongside the backend changes in the same feat commit. Subject tracer (PR #280) shipped 125 lines of `api-types.ts` text-only churn; Stundentafel tracer shipped 25 lines. Plan-time "fe:types produces zero diff" assertions in tenancy specs are wrong; expect the JSDoc churn and stage it.

## Testing

- **Test fixtures, not imports.** `pytest --import-mode=importlib` requires shared helpers be fixtures in `conftest.py`, not plain imports.
- **Scheduling entity factories** live in `backend/tests/scheduling/conftest.py`. Join-table rows have no factory; construct inline with `db_session.add(...)` + `flush()`. `Lesson.preferred_block_size` is NOT NULL with no server default; always set it.
- **`TimeBlock.start_time` / `end_time` are `datetime.time`,** not strings.
- **`Teacher` has no `qualifications` relationship; query `TeacherQualification` directly** (see `_build_teacher_detail` in `scheduling/routes/teachers.py`). Same for `TeacherAvailability`.
- **`async with db_session.begin_nested():` for tests that expect `IntegrityError`.** A bare `rollback()` in `finally:` escapes the outer savepoint and drops setup rows.
- **`Lesson.teacher_id` is pin-only.** The solver picks among `teacher_candidates` when null. `POST /generate-lessons` validates qualified-teacher coverage up front and returns 422 (`code="missing_qualified_teacher"`, `subject_ids`, `subject_short_names`) if any subject has no qualified teacher.
- **Teacher-side hard-availability constraints translate to existing solver-input channels, not new solver-core fields.** `Teacher.working_days` (Teilzeit) lands in two places in `build_problem_json`: (a) `_extend_blocked_times_for_off_days` appends off-day `(teacher_id, time_block_id)` rows to `teacher_blocked_times` so LAHC's neighbour generator never proposes those slots; (b) `_candidates_for_lesson` intersects the per-teacher allowed-TimeBlocks against `working_days` so the candidate set is empty when no overlap exists. Both sides are load-bearing: omitting (a) lets the search-time RNG land on an off-day; omitting (b) surfaces empty-candidate teachers as `NoFreeTimeBlock` violations instead of clean filtering. Reuse the same channel pair for future teacher-side hard constraints (weekly meetings, school-wide pull-outs) rather than widening solver-core's `Teacher` (which cascades to ~90 sites).
- **Solver post-condition validators raise `ValueError`, not soft violations.** `solver_io.run_solve` catches `(ValueError, RuntimeError)` and re-raises; tests must assert `status_code == 200` BEFORE asserting on `body["violations"]`.
- **`caplog` records expose `extra=` keys via `record.__dict__[key]`,** not `record.key`.
- **Settings tests construct `Settings` directly,** not `get_settings()`. Use `Settings(_env_file=None)  # ty: ignore[missing-argument, unknown-argument]`.
- **Ruff `PLC0415` rejects in-function imports.** Hoist to module top-level.
- **Ruff `S101` rejects `assert` in non-test source.** Restructure the data flow so the narrowed value travels through the data structure (carry the discriminator as a tuple key element) rather than asserting after a filter.
- **`QualityIssue.detail` is `dict[str, object]`,** not `str`.
- **Middleware integration tests use `httpx.ASGITransport(app=build_app(env="dev"))`** + `AsyncClient` + `caplog.set_level(...)`.
- **Cross-test-module helpers import as `from tests.<module>`,** not `from backend.tests.<module>` (no `backend/__init__.py`).
- **Conftest module-load env mutations need `# noqa: E402`** on trailing `klassenzeit_backend` imports.
- **`app.state.<name>` set in `lifespan` must be mirrored in the test `client` fixture** in `backend/tests/conftest.py`. `httpx.ASGITransport` skips `lifespan`, so without the mirror request handlers raise `AttributeError`. Pattern: `settings`, `rate_limiter`, `solver_progress`.
- **Per-request long-running state lives in an `app.state.<name>` dict + a `@contextmanager` lifecycle.** Pattern: `app.state.<registry> = {}` set in `lifespan`; a `register_<thing>(registry, *, key, ...)` context manager registers an entry, `yield`s it, and removes it in `finally:` so a crashing handler still leaves the registry clean. Sibling read / cancel routes look up the key and return 404 when absent. Template: `backend/src/klassenzeit_backend/scheduling/progress.py` (`register_progress` + `RegistrationEntry`). ADR 0039.
- **Backend capability gaps surface as a structured `logger.warning(...)` + fall-through, not a 4xx.** When the backend wires a new capability through one solver path (live progress on the three LAHC backends) but not yet through another (CP-SAT), the unsupported path logs `solver.solve.<capability>_unsupported` with `extra={"backend": ...}` and continues with the legacy code path so the request succeeds. The route is uniform; the capability degrades. Pattern: `progress_handle is not None` branch in `solver_io.run_solve`'s `case "cpsat":`. ADR 0039.
- **Sibling-pin emission in `solver_io.collect_pinned_placements` is unconditionally `kind: "hard"`.** Sibling placements (other classes' rows in a per-class re-solve) are immovable regardless of the user-facing `pin_kind`, because the re-solve only mutates the target class's placements. Only `collect_own_class_pins` / `collect_all_pins` propagate `row.pin_kind.value`. New pin-kind-aware axes inherit this distinction.
- **Integration tests that force a solver-side soft-cost-axis miss should use a hard-constraint conflict (teacher double-book, room blocked, daily cap saturation), not an optimisation tiebreak.** Hard-constraint conflicts force the solver to route around the soft cost regardless of seed or weight tweaks; tiebreak-based forcing drifts under `KZ_SOLVE_DEADLINE_MS_*` reshuffles. Template: `test_soft_pin_solver_integration.py` (forces a soft-pin miss via teacher conflict at the pinned slot).
- **New required fields on solver `Solution` flow through `filter_solution_for_class`** to land on `ScheduleResponse`. Adding a field on solver-core's `Solution` plus the matching field on the Pydantic response model is insufficient if `filter_solution_for_class` doesn't pass it through; the route's `model_validate(filtered)` call silently drops missing fields back to their default.
- **`ScheduleReadResponse` (GET /teachers|rooms|classes/{id}/schedule) is distinct from `ScheduleResponse` (POST /classes/{id}/schedule).** A new field surfacing on solve-time responses lands on `ScheduleResponse` via `filter_solution_for_class`; the same field on read-time responses needs explicit addition to `ScheduleReadResponse` plus a populating query at the manual-construction site (`read_schedule_for_*_route`). Pinning tests like `test_get_schedule_for_teacher_empty_placements_response` assert the exact dict shape and break when a field is added without default; widen those in the same commit. Resource-scoped fields populate at one read route only and default to `[]` elsewhere: `supervision_assignments` populates only at the teacher read route; `quality_issues` populates only at the class read route (and via the sibling `GET /api/classes/{class_id}/quality-issues`). The pinning tests for the unpopulated routes assert `[]`; do not back-fill at sibling routes without changing the resource-scoping intent.
- **Nullable complex-model fields on resource-scoped reads (`T | None`) — route decides empty.** For fields like `quality_report: QualityReportResponse | None = None`, the populating route decides the empty-resource case: either return a zero-valued `T` (orchestrator always builds one) or return `None`. `quality_report` returns a zero-`QualityReportResponse` on the class + teacher GETs even pre-solve (per-axis orchestrators build an all-zero report from no placements); room routes leave it `None`. Shape-pin tests follow the route's choice, not the schema default.
- **School-wide solver outputs persist with WeekScheme scoping, not class scoping.** The schedule POST is a per-class route, but solver outputs that describe a school-wide artifact (Hofpause supervision rota) overwrite at WeekScheme granularity: `persist_supervision_assignments(db, week_scheme_id, solution, *, school_id)` deletes every row whose `time_block_id` belongs to the WeekScheme, then inserts the fresh rota stamped with the caller's `school_id`. A subsequent per-class re-solve overwrites the whole rota, which is correct because the supervision pass emits one entry per break-kind TimeBlock on the affected scheme. Sibling reads attribute by filter (`read_supervision_assignments_for_teacher(db, teacher_id, *, school_id)` selects WHERE `teacher_id = ? AND school_id = ?`) and return `[]` when empty rather than 404; the GET handler's existing per-aggregate 404 already covers the not-found path.
- **pytest-xdist gives each worker its own database** via `backend/tests/_xdist_db.py` (ADR 0019). Two concurrent `mise run test:py` invocations conflict on the suffix-less `klassenzeit_test`; run flake loops sequentially. Alembic migrations cache via a Postgres template DB; schema-changing PRs must drop the template and per-worker DBs first (`DROP DATABASE IF EXISTS klassenzeit_test_template; klassenzeit_test_gw0; ...; klassenzeit_test`). `psql` is NOT on the host; drop via `podman exec klassenzeit-db-1 psql -U klassenzeit -d postgres -c "DROP DATABASE IF EXISTS <name>;"`.
- **Per-backend deadlines in `.env.test`.** Zeroes `KZ_SOLVE_DEADLINE_MS_*` for all solver backends; one-test override via `monkeypatch.setitem(app.state.settings.solve_deadline_ms_by_backend, "<backend>", 5000)`. ADR 0038.
- **`KZ_SOLVER_BACKEND` selects the backend** (`Literal["lahc", "lahc_rr", "lahc_rr_kempe", "cpsat"]`, default `lahc_rr`). Default pinned by `test_solver_backend_default_is_production_choice`; flip assertion and ADR in lockstep. ADR 0030 / 0031 / 0032 / 0037.
- **Quality-bar tests the system does not yet meet ship as `pytest.mark.xfail(strict=False)`** paired with a sibling item in `docs/OPEN_THINGS.md`.
- **Route handlers that construct response objects manually** (subject CRUD, `read_schedule_for_class`, `read_schedule_for_teacher`, `read_schedule_for_room`) must include any new schema fields explicitly. `model_validate(orm_row)` callers auto-flow.
- **Structured 422 detail dicts use `{"code": str, ...domain fields}`** for machine-readable error codes. FastAPI accepts `HTTPException(detail=<dict>)` natively; the `code` discriminator drives frontend i18n.
- **`scheduling/schemas/__init__.py` is intentionally bare;** every schema is imported directly from its submodule.
- **`ViolationResponse.kind` Literal lives in `scheduling/schemas/schedule.py`.** Adding a new `ViolationKind`: widen the Literal, `mise run fe:types`, extend the frontend exhaustive switch + i18n keys, update the closed-enum tests. Land all four in one commit.
- **`QualityReport` field-set is pinned exhaustively in two tests:** `tests/scheduling/test_schedule_route.py::test_schedule_post_response_carries_quality_report` and `tests/scheduling/test_schedule_all_respect_pins.py::test_schedule_all_response_carries_quality_report` both maintain a frozen `expected_fields` set-equality assertion. Adding a `QualityReport` field touches both tests in lockstep with the Pydantic mirror (`schemas/quality_report.py`); `extra="forbid"` on `QualityReportResponse` 422s the route if the mirror drifts.
- **`Placement.position` is the lesson ordinal; `Placement.time_block_position` is the raw `TimeBlock.position`.** The loader `quality_checks.load_placements(db)` projects raw → ordinal via `build_lesson_ordinal_map` and stores both. Predicates whose logic depends on lesson sequence (`check_interior_gaps`, `check_day_length`) read `position`; cell-emitting predicates (`check_room_hop`, `check_home_room_ratio`, `check_day_length`, `check_class_teacher_subject_share`) serialize cells using `time_block_position` so the frontend grid (which keys by raw `TimeBlock.position`) matches. After ADR 0040, lesson positions are sparse (einzügig day: 1,2,4,5,7,8). New quality consumers call `compute_quality_issues(db, class_id)` which builds all lookups and runs the six predicates with the module-level threshold constants (`MAX_DAY_LENGTH_ORDINAL`, `MIN_HOME_ROOM_RATIO`, …); do not call individual predicates from a route handler.
- **Seed-shape tests pinning `[b.position for b in day_blocks] == list(range(1, N))` are a known sensitivity surface.** When seed positions change (e.g. 6 → 8 with breaks), audit `backend/tests/seed/test_demo_*_shape.py` for `range(1, 7)` / `range(1, 9)` patterns and `TimeBlock` count assertions; update in the same commit as the seed change.
- **Alembic head check before writing `down_revision`.** `ls backend/alembic/versions/ | sort | tail -1` can lag the real head when intermediate revisions land. Verify with `cd backend && mise exec -- uv run alembic heads` (the bare `alembic` binary is not on PATH; `mise exec -- alembic` fails with "No such file or directory"); pin `down_revision` to the actual head, not the file-sort tail, or `alembic upgrade head` errors with "multiple head revisions".

## Logging

- **Structured logs use `logger.info("event.name", extra={...})`.** `JsonFormatter` merges `extra=` keys at top level (ADR 0016). Reserve `event` as a stable identifier.
- **Per-request `request_id` propagates via the `request_id_var` ContextVar.** A `RequestIdFilter` injects it onto any `LogRecord` in the request scope; routes do not thread `request_id` through `extra=` manually.
