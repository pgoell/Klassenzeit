# Klassenzeit: Solver Rules

Applies to the `solver/` Cargo workspace. On top of `.claude/CLAUDE.md`.

## Workspace layout

- **`solver-core`**: pure Rust library (algorithm, constraint model, typed errors; no PyO3, no Python, no I/O).
- **`solver-py`**: `cdylib` crate wrapping `solver-core` via PyO3 (`0.28`); maturin builds it into the `klassenzeit_solver` Python package. Thin wrappers only.
- **`solver-bench`**: Rust binary running the feasibility bake-off. Imports `solver_core::test_fixtures` (default-on `fixtures` feature). Manual CLI, no external runtime deps. ADR 0029.
- **Root** `Cargo.toml` declares `edition = "2021"`, `rust-version = "1.85"`, `resolver = "2"`, shared dev-dep `proptest = "1"`; root `pyproject.toml` is a uv workspace; backend pulls `klassenzeit-solver = { workspace = true }`. Hand-maintained `.pyi` stubs in `solver/solver-py/python/klassenzeit_solver/*.pyi` ship in the same commit as a Rust binding change.

## solver-core rules

- **`#![deny(missing_docs)]` at crate root;** every `pub` item needs a `///` rustdoc. `clippy::doc_lazy_continuation` flags `+` at the start of a continuation (use `and` / `plus` or indent two spaces). Errors use `thiserror`, one enum per boundary; no `anyhow`. Deterministic under test: no `SystemTime::now()`, no `thread_rng()`; randomisation seeded via a public-API parameter.
- **`define_id!` macro derives `Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize`.** Adding a `BTreeMap<<IdType>, _>` field (or anywhere `Ord` is needed on a solver-core ID newtype) goes through the macro derive list, not per-site annotations. `PartialOrd, Ord` are the load-bearing additions for `BTreeMap` keys; all seven ID types share the derive set.
- **Tests.** Inline `#[cfg(test)] mod tests` for unit, `solver-core/tests/*.rs` for integration. Shared fixtures: `solver-core/tests/common/mod.rs`.
- **Property-test generator widenings need a 5x128 local sweep before commit:** `for s in 1..=5; do PROPTEST_CASES=128 PROPTEST_SEED=$s cargo nextest run -p solver-core --test <file>; done`. For divisibility constraints, construct values from a formula in the closure rather than `prop_assume!`-filtering.
- **Bench targets cannot host libtest tests.** Put helper + tests in `benches/<name>.rs` and `#[path]`-include from both the bench and a one-line `tests/bench_<name>.rs` (template: `benches/percentile.rs` + `tests/bench_percentile.rs`).
- **Lowest-delta greedy iterates pre-sorted indices.** `solve_with_config` sorts `time_blocks` by `(day_of_week, position, tb.id)` and `rooms` by `id`; the picker's tiebreak and early-exit depend on those orderings, and LAHC's neighbour generator must reuse them.
- **Soft-score evaluation must not allocate inside `try_place_block`.** Compute `new_min` / `new_max` / `len_after` from the existing `&Vec<u8>` plus the proposed `pos`; call `score::gap_count` (or `gap_count_after_window_insert` for n-block windows). LAHC's delta evaluation mirrors this.
- **`try_place_block`'s picker scores total = slice + home_room_penalty, persists slice into `state.soft_score`.** `BlockCandidate` carries both; window-level pruning compares on slice (a lower bound on total). Mixing home_room into the persisted score contaminates the slice contract LAHC's Change move and R&R's recompute rely on.
- **Per-iteration `debug_assert_eq!(running_X, full_recompute_X)` at the LAHC iteration tail catches incremental-delta drift.** Gate under `#[cfg(debug_assertions)]`; release compiles it away. Applies to any running total: slice, canonical, partition gap counts.
- **Per-class-max canonical summands use temp-swap delta in Change move,** full-recompute in Kempe (snapshot pre-attempt, recompute post-apply, fold into `canonical_delta`), and ride R&R's existing `score_solution` recompute.
- **New soft costs landing in `score_solution` must reach the Change-move canonical-score update path.** R&R, Kempe, and `try_change_block_move` (n>1) accept paths already recompute via `score_solution`; the n=1 Change path (`try_change_move_n1`) is delta-only. Either thread a per-move delta into `try_change_move_n1`'s `canonical_delta`, or set `state.canonical_score = score_solution(problem, placements, weights)` at the Change accept site. Skipping both leaves the per-iteration `debug_assert_eq!` to fire under `cfg(debug_assertions)`. Supervision spread uses the recompute path (`solver/solver-core/src/lahc.rs::try_change_move_n1`).
- **`GreedyState` carries two scores.** `search_score_slice` (class_gap + teacher_gap + subject_pref) is the LAHC search-time hot-path objective; `canonical_score` (slice + prefer_home_room + class_day_balance + per-class-max + class_teacher) is the accept-time objective. Both maintained in lockstep across Change, R&R, Kempe, and home_room_repair.
- **LAHC RNG draw count is invariant across loop branches** (every iteration of the Change branch consumes exactly three `random_range` calls; R&R, Kempe, and home-room-repair branches each consume from their own dedicated RNG); the determinism property test relies on this. R&R uses a separate `SmallRng` seeded from `config.seed.wrapping_add(1)`; Kempe from `wrapping_add(2)`; home-room-repair from `wrapping_add(3)` (one draw per fired iter: the placement index). ADR 0050.
- **R&R move semantics.** Block-level ruin (Doppelstunde as one N-block), skip pinned and lesson-group members. `rr_attempt` ruins only; `rr_rescue_attempt` handles FFD-unplaced lessons by ruining all of the target's placements plus one same-class sibling anchor (so the target's `(class, subject)` lock clears and `try_place_block` re-picks a teacher), then re-places the target and recreates the sibling block (lesson-group rescue: `rr_rescue_group_attempt`). Accept: reject on `failed_recreates > 0`, otherwise standard LAHC; rescue's gate is feasibility-only. `SolveConfig.lahc_rr_k` (default 5) caps chain width.
- **`score::score_solution` does NOT include hard violations.** Adding a placement strictly increases canonical, so a feasibility-restoring move raises canonical even when removing a hard violation. LAHC's running-best snapshot is lexicographic on `(placements.len() desc, canonical asc)`, not canonical alone. Rescue's accept gate is a direct feasibility check.
- **Post-LAHC violations filter in `solve_with_config_stats`** drops FFD-time `{NoFreeTimeBlock, TeacherOverCapacity, NoSuitableRoom, LessonGroupSplit}` rows whose lesson's placement count `>= hours_per_week`.
- **Kempe move semantics.** Two-day same-position swap of a block-anchor; BFS over teacher+class conflict graph at the destination window builds the chain (bounded by `config.lahc_kempe_max_chain`, default 8). Block-aware, pin-skip, group-skip. Asymmetric acceptance. BFS new-neighbour set sorted by `LessonId.0`; BFS enforces bipartiteness via per-edge same-color cross-check at insertion (adjacent-pair alone misses same-color collisions because the read-only `placements` view does not reflect chain destinations). Same shape applies to any future BFS-based ruin+apply move.
- **BFS-shaped move sites read teacher via `lesson_teacher_in_state(state, lesson)`,** not `lesson.assigned_teacher_id()`. The lock map in `state.class_subject_teacher` may bind a different teacher than the static field. Thread `state: &GreedyState` into any new BFS-shaped or ruin+apply move.
- **New cross-day LAHC move helpers must check `state.locked_room` at every destination `(class, day, subject)` triple.** Mirror `try_change_move_n1`'s `new_day_lock` path: when a lesson moves to a new day and that `(class, day, subject)` triple already has a locked room, the move must use the locked room (or reject when infeasible). Unit tests for the helper alone do not surface this; `solver-core/tests/lahc_supervision_invariant.rs` ("room hopping for class ... day X subject ...") is the canary. Applies to `try_change_block_move` (n>1 cross-day path), `try_swap_move` (cross-day swap), and any future LAHC move that shifts a placement's day.
- **New same-day room-only LAHC moves must walk siblings on `(class, day, subject)` to preserve `validate_no_room_hopping`.** `state.locked_room` covers cross-day moves only; a same-day room rewrite (e.g. `try_home_room_repair_move`'s (A)/(B) paths) does not consult it. The reject set: for each member class of the moving placement, scan all other placements; reject if any sibling shares `(class_id, tb.day_of_week, lesson.subject_id)` AND lives in a room different from the proposed target. Symmetric for the displaced participant in any room-swap path. Helper `would_split_class_day_subject_room` in `lahc.rs` is the reference. Canary: `validate_no_room_hopping` at the post-solve `?` call in `solve_with_config_stats` propagates `Err(Error::Input("room hopping ..."))` and `solver_io.run_solve` re-raises as a `ValueError`. The single-iter integration test `test_grundschule_schedule_meets_quality_bar` may not surface the split (it depends on per-class lesson generation); the seed-driven `test_seeded_grundschule_dreizuegig_solves_without_pinned_teachers` is the broader canary.
- **LAHC move helpers that rewrite `Placement.room_id` must keep `state.locked_room` for the affected `(class, day, subject)` triple in sync.** The cross-day read-side rule above is one half; the write-side counterpart is: any same-day room-rewrite accept (Path A / Path B-shape in `try_home_room_repair_move`) must update the corresponding `state.locked_room[(class, day, subject)]` entry's `RoomId` field. No-op when no entry exists (the map is Some-only). Sites today: `try_home_room_repair_move`'s two accept blocks (`lahc.rs`); future same-day room-rewrite kernels follow the same shape. Symptom on miss: `validate_no_room_hopping` or `validate_no_double_booking` panics at post-solve from a downstream Change move (`try_change_move_n1`'s `new_day_lock` path) reading the stale lock and placing a sibling at the original room. The single-iter integration tests do not surface this reliably; the production-budget bench cross-section (rule 8 LAHC-move exception) is the canary. Item 88, ADR 0050.
- **`score_solution`'s per-class-day partition shape must match `state.class_positions`'s dedup'd shape.** Lesson-group co-placements push multiple entries while `state.class_positions` keeps one. Mismatch surfaces as `state.canonical_score` drift. Any axis reading partition counts via `.len()` must `sort_unstable + dedup` first.
- **`test_fixtures::*_fixture()` builders set `class_teacher_id: None`.** The `prefer_class_teacher` axis is inert; Rust regression tests must stamp `class_teacher_id` explicitly (pattern: `lahc_unpinned_test_assign_class_teachers(&mut problem)`).
- **Audit every LAHC-internal helper building a per-(teacher, ...) HashMap snapshot for `lesson.assigned_teacher_id()`;** route through `lesson_teacher_in_state` or `p.teacher_id`. Established sites: `kempe_snapshot_pre_score`, `running_slice_from_placements`. Post-solve readers consume `Placement.teacher_id` (sites: `validate_no_double_booking`, `score_solution` / `quality_report` `by_teacher_day`, `try_place_group`'s per-member path); pre-solve seed sites (`validate_pins`, `seed_greedy_state_from_pins`) consume `pin.teacher_id` / `pl.teacher_id`.
- **`try_place_group` picks teacher per-member from `teacher_candidates`,** sibling to room's `taken: HashSet<RoomId>`: a `chosen_teachers: HashSet<TeacherId>` for the group window. Apply-time: `state.class_subject_teacher.entry((class, subject)).or_insert(chosen)` so subsequent block placements honour the lock.
- **Ruin+apply rollback: remove exact placements, do not re-ruin by lesson+day.** Capture `(LessonId, time_block_id, room_id)` rows at apply and remove only those on rollback. Snapshot any `pub(crate)` `GreedyState` map a move mutates (today: `class_subject_teacher`); restore verbatim. Rollback paths read keys from the row (`row.teacher_id`, `p.teacher_id`), not `lesson_teacher_in_state` (the lock map is drifted until rollback completes). Shared helper: `rr_remove_row_bookkeeping`. Soft-score delta: snapshot pre/post partition (Kempe's `kempe_post_score_delta`) or full `score_solution` recompute (R&R); do not differential per-member.
- **FFD can pack multiple N=1 blocks of one lesson on one day;** `rr_collect_anchors` filters anchors whose count exceeds `preferred_block_size`, so every anchor-based move inherits the invariant.
- **`SolveConfig.max_iterations` is test-only;** production callers leave it `None`.
- **Algorithm-site rollback unit tests must stamp the real teacher on seeded Placements,** not `TeacherId(Uuid::nil())`. Rollback reads `row.teacher_id`; a nil placeholder silently no-ops the remove.
- **`solve_json_with_config(json, deadline_ms, lahc_rr_period, lahc_kempe_period, lahc_home_room_period)` is the deadline-configurable adapter** the backend uses; `solve_json(p)` is the legacy 200ms-default delegate; `deadline_ms = None` skips LAHC. `lahc_rr_period` / `lahc_kempe_period` / `lahc_home_room_period` are `Option<u32>` (move-period overrides; all default to `None` = disabled, preserving pre-Sprint-4 single-Change behaviour). Solver-py mirrors as `klassenzeit_solver.solve_json_with_config(problem_json, deadline_ms, lahc_rr_period=None, lahc_kempe_period=None, lahc_home_room_period=None)`. Binding contract tests use `deadline_ms=None`. ADR 0020, ADR 0050 (home-room kernel). `solve_with_config_stats -> (Solution, SolveStats)` is the bench-only stats surface; `solve_with_config` wraps it. ADR 0034. `solve_with_progress(problem, config, beacon)` threads an `Arc<ProgressBeacon>` for live progress + cooperative cancel without changing `solve_with_config_stats`'s signature; the JSON sibling is `solve_json_with_progress(problem_json, deadline_ms, beacon, lahc_rr_period, lahc_kempe_period, lahc_home_room_period)`. ADR 0039.
- **Optional-capability cascade goes through a private `_inner(..., capability: Option<&T>)`.** When adding a new optional capability (progress beacon, telemetry sink, future cancel token) to a public solver entry point, do NOT widen the existing public function's signature; introduce a private `solve_with_config_stats_inner(problem, config, capability: Option<&T>) -> ...`, delegate the existing public function with `None`, and add a sibling public function (`solve_with_progress`, `solve_with_telemetry`, etc.) that delegates with `Some(...)`. The no-capability path must remain byte-equal to the pre-feature path; pin with a seed-sweep determinism test (template: `solver-core/tests/progress.rs`). Capability blocks must consume zero RNG draws when not threaded; the LAHC inner-loop determinism property test relies on this.
- **`Arc<ProgressBeacon>` is the canonical cross-thread channel for solver-internal observers.** `AtomicU64` / `AtomicBool` with `Relaxed` ordering; the only invariant is "every read returns some value the loop wrote", no happens-before relationships across atomics. No allocation in the hot path; the LAHC loop calls `beacon.record(...)` once per iteration and reads `beacon.cancel_requested()` at the loop head. Solver-py wraps the Arc in a `ProgressHandle` `#[pyclass]`; the backend hands the handle to the solver thread via `asyncio.to_thread(_solve_json_with_progress, ...)`. Cancel is cooperative: the loop exits at the next iteration boundary, sets `Solution.was_cancelled = true`, and returns the running-best incumbent. ADR 0039.
- **`#[serde(deny_unknown_fields)]` makes `mise run solver:rebuild` mandatory after a Rust-side field add** (stale wheel symptom: `Error::Input(reason="unknown field 'foo'")`). `ViolationKind` variants must be unit, not struct; per-variant data goes on `Violation` as an additive `#[serde(default)]` field (e.g. `Violation.reason: Option<String>`, ADR 0027).
- **`Violation.lesson_id` is required.** For violations that have no responsible lesson (e.g. `SupervisionGap`, which describes a Hofpause slot with no eligible supervisor), use `LessonId(Uuid::nil())` as a sentinel and carry the diagnostic in `reason` (`"day=<d> position=<p> candidates=0"`). Widening to `Option<LessonId>` would ripple through every consumer; the nil-sentinel + reason-string discriminator matches `PinnedConflict`.
- **Post-solve passes that score in the hot path AND finalise after split into `_spread` (count-only) + `_full` (assignments + violations + spread).** When a soft-cost axis needs both a per-iteration scalar contribution to `score_solution` and a richer artifact attached to `Solution` (rota rows, violation entries), expose two entry points over one inner helper. Hot-path `compute_<axis>_spread` returns just the scalar and allocates nothing beyond a running-count vector; finalisation `compute_<axis>_full` returns the `(assignments, violations, spread)` triple and runs once at `Solution` build time. Both share the inner walker so the spread value matches by construction. Template: `solver-core/src/supervision.rs` (`compute_supervision_spread` + `compute_supervision_full`).
- **Adding a field to `Problem` cascades to ~75 struct-literal sites across ~32 files** in src + tests + benches + solver-bench. `Subject`, `ConstraintWeights`, `SolveConfig`, `SchoolClass`, `PinnedPlacement`, `Solution` follow the same shape but at lower cardinality. **Adding a field to `Teacher` cascades to ~90 sites** because every fixture builder constructs a Teacher. **Adding a field to `Lesson` cascades to ~120 sites** because every property-test generator, every fixture builder, and every hand-rolled test harness builds Lessons (ADR 0044 added `pre_buffer_minutes` + `post_buffer_minutes`; the perl-sweep `s/(preferred_block_size: \d+,)/$1 pre_buffer_minutes: 0, post_buffer_minutes: 0,/g` covered 124 sites in one pass, with manual cleanup for proptest closures and non-`preferred_block_size`-bearing literals). `cargo build --workspace --all-targets` enumerates offenders; `#[serde(default)]` handles JSON but not source-level constructors. A perl `-i -pe` sweep over `max_hours_per_week: <int>` misses `.map(|i| Teacher { ... max_hours_per_week: arr[i], })` patterns and single-line literals; rebuild after the sweep and fix the remaining E0063 errors manually. Future `SolveConfig` widenings land cleanest after a tidy-first commit migrating exhaustive literals to `..SolveConfig::default()`. **`rustfmt` cannot reach into `prop_compose!` macro bodies**, so the perl sweep's single-line `vec![], <new_field>: 0,` shape will trip `cargo fmt --check` on proptest sites (typical hit list: `tests/lahc_property.rs`, `tests/score_property.rs`, `tests/properties.rs`, `tests/quality_property.rs`, `tests/teacher_uniformity_property.rs`); a follow-up perl pass splitting those lines manually clears the check.
- **Per-day caps** (`Subject.max_hours_per_day`, `SchoolClass.max_lessons_per_day`) are enforced via legality pruning in `try_place_block` / `try_change_move_n1` / `try_change_block_move` / `try_swap_move`. Bookkeeping on `GreedyState.subject_hours_by_class_day` and `lessons_by_class_day`. ADR 0033.
- **LAHC outer loop exits at the conjunctive objective floor:** `placements.len() == placements_expected && state.canonical_score == 0`. Both must be at the floor. ADR 0033, ADR 0038. LAHC returns the running-best `(placement-count, canonical)` incumbent, lex order `(placements.len() desc, canonical asc)`.
- **Post-condition validators septet** in `solver-core/src/validate.rs`: `validate_no_room_hopping`, `validate_daily_caps`, `validate_no_double_booking`, `validate_placement_teacher_in_candidates`, `validate_class_subject_teacher_uniformity`, `validate_no_lesson_on_break_slot` (kind=break filter), `validate_travel_buffer` (non-zero pre/post buffer minutes; rejects adjacent class/teacher placements and day-edge placements; `Problem.pre_first_slot_grace_minutes >= lesson.pre_buffer_minutes` relaxes the pos=0 reject only, ADR 0044). One Result-form call per validator at the tail of `solve_with_config_stats`; `Err(Error::Input)` propagates via `?`. Cardinality is `>` only (over-placement), not `!=`. `validate_no_double_booking` exempts lesson-group co-placement from the class check. **Relaxing a `pos == 0` rejection on a `u8`-typed position requires guarding the subsequent `let prev_pos = pos - 1;` read with `if pos > 0`**, else debug-build panics on subtract overflow and release wraps to 255 (silent bug). Validator and `would_violate_*` predicate sites both apply.
- **Lesson-placement TimeBlock enumeration sites that must filter on `kind == Lesson`** (adding a new TimeBlockKind that should not host lessons needs all of these): `solve.rs::tb_order` (FFD), `solve.rs::unplaced_kind` open-slot probe, `lahc.rs::tb_order` (R&R recreate), `lahc.rs::tb_by_day_pos` (Kempe seed / chain destination lookup), `lahc.rs::try_change_block_move` and `lahc.rs::try_change_move_n1` destination kind checks (after the three RNG draws to preserve the determinism RNG-budget invariant), `ordering.rs::ffd_order`'s `tbs_by_day` contiguity scan, and the validator above. Supervision pass in `supervision.rs` is the only consumer of `kind == Break` rows today.
- **`try_place_block` has three callers, not two:** `solve_with_config_stats` (FFD), `lahc.rs::rr_attempt`'s recreate, and two unit-test invocations. `try_place_group` has one production caller. Plans estimating "two call sites" miss `lahc.rs`.
- **Inter-placement hard-constraint pruning must be symmetric at every move site.** When a constraint relates two placements (A blocks B AND B blocks A), the move-site predicate must check BOTH directions: "would the moved lesson violate against existing placements?" AND "would any existing placement now violate because the moved lesson newly occupies its adjacent slot?". A one-sided check passes unit tests on the moved-lesson side and silently lets non-buffered lessons drift into the adjacent slot of an existing buffered placement (travel_buffer was the first such constraint; ADR 0044). Thread `placements: &[Placement]` (or equivalent) into the pruning helper so the existing-placement side can be scanned at each LAHC site; unit tests must cover both directions explicitly.
- **Post-condition validators walking multi-slot blocks need a block-anchor guard.** Validators that iterate `placements` and check adjacent-slot semantics (`pos - 1`, `pos + preferred_block_size`) must filter to the BLOCK ANCHOR (first slot of the block) before applying the check; non-anchor placements (slot 2, 3, ... of a Doppelstunde) see neighbors that are the SAME block, and `pos + preferred_block_size` overshoots the actual block end. Either pre-filter via `is_block_anchor(placements, lesson_id, day, pos)` or skip self-conflicts by comparing `lesson_id`. `validate_travel_buffer` (ADR 0044) uses the lesson_id-self-conflict-skip plus a block-anchor check on the post-side. Same shape applies to any future placement-adjacency validator.
- **FFD picker's first-pick capacity check requires whole-lesson hours, not block n** when no existing lock and no teacher pin: gate is `current + lesson.hours_per_week > max`. After the lock exists the per-block ceiling is correct.
- **FFD lesson ordering's primary key is `teacher_candidates.len()` ascending (scarcity first),** then same-room-aware eligibility, then `LessonId`. New tiebreaks insert after the scarcity primary key.
- **`try_place_block`'s window-level picker uses strict `<` end-to-end.** Both the room scan within a window and the cross-window comparison resolve ties to the first-walked candidate.

## solver-py rules

- **Thin wrappers only;** every `solver-core` symbol goes through a `#[pyfunction]` / `#[pyclass]` in `solver-py/src/lib.rs`. No algorithm logic.
- **Release the GIL** via `py.detach(|| ...)` (PyO3 0.28 renamed from `allow_threads`). Errors map: client mistakes to `PyValueError`, solver-internal to `PyRuntimeError`. Placement failures come back as `Violation` entries in `Solution`, not errors. Use `#[pyo3(name = "...")]` when the Rust fn name must differ from the Python-facing name; `scripts/check_unique_fns.py` rejects duplicate `fn solve_json` definitions.
- **`#[new]` ctors bind to Python `__init__` via the attribute,** so the Rust fn name is free. When `scripts/check_unique_fns.py` flags a collision on `fn new`, rename the Rust ctor (e.g. `fn py_new_progress_handle`) instead of adding `#[pyo3(name = "new")]`; the binding is unaffected.
- **Python tests exercise the binding contract,** not the algorithm (encoding, GIL release, error conversion).
- **Maturin dev loop.** `mise run solver:rebuild` (debug-profile wheel, seconds) for source-only edits; `uv sync` for `pyproject.toml` / `Cargo.lock` / workspace `Cargo.toml` edits. The debug wheel keeps `cfg(debug_assertions)` ON, so the LAHC per-iteration `debug_assert_eq!(state.canonical_score, score_solution(...))` fires inside `klassenzeit_solver` during `mise run test:py`; a backend test panic of that shape lives in `solver-core/src/lahc.rs`.
- **CP-SAT's Python-facing entry is `klassenzeit_solver.cpsat.solve_cpsat_json(problem_json: str, deadline_ms: int | None, seed: int = 1) -> str`.** JSON string in, JSON string out; convert via `json.dumps` / `json.loads`. There is NO `cpsat.solve(dict)` shortcut; pytest fixtures that hand a dict directly fail with `TypeError`. Same shape applies to `klassenzeit_solver.solve_json(problem_json: str) -> str`.
- **CP-SAT lives in `klassenzeit_solver.cpsat` as pure Python** (peer-Python algorithm is allowed). `score_solution_json` and `quality_report_json` are the cross-backend scorers `cpsat.py` calls post-solve so all backends compare on the same Rust scorer. ADR 0030. CP-SAT objective mirrors `score_solution` exactly: adding a soft-cost axis touches three sites (`_W_<AXIS>`, `_objective_<axis>_term`, a summand in `_emit_objective`); CHANGING an existing weight in `PRODUCTION_ACTIVE_WEIGHTS` touches the Rust const PLUS the Python `_W_<AXIS>` mirror in `cpsat.py` (the mirror is NOT auto-derived from the PyO3 binding); property test pins `solver.objective_value == score_solution_json(...)`. Class non-overlap dedupes by `(class_id, lesson_group_id)` so multi-class lesson groups don't force the model INFEASIBLE. OR-Tools API uses snake_case (`add`, `new_bool_var`, `minimize`, `solve`); camelCase aliases work at runtime but `ty` doesn't see them. INFEASIBLE is distinguishable from UNKNOWN by wall-clock. **Pin-kind-aware axes must filter `_emit_pinned_placements` so only `kind == "hard"` is force-placed;** otherwise a soft-cost-axis miss becomes either trivially zero (force-placed) or INFEASIBLE (when the soft pin conflicts with hard constraints), and the parity test passes only by construction.
- **PyO3 wrappers have two `.pyi` stubs:** `klassenzeit_solver/__init__.pyi` (package-level) and `klassenzeit_solver/_rust.pyi` (submodule consumed by `cpsat.py`). Update both.
- **`PRODUCTION_ACTIVE_WEIGHTS` is the canonical weight set,** a single `pub const` in `solver-core/src/types.rs`. Bench, `solve_json_with_config`, `score_solution_json`, and any cross-backend scorer reference it; do not re-hand-write the literal.

## Clippy and allows policy

No `#![allow(...)]` at crate root. No `#[allow(...)]` at item scope unless (1) a specific lint is wrong in this block with a sibling `// Reason: ...` comment, or (2) PyO3 macro-expansion noise. No `#[allow(dead_code)]` outside `#[cfg(test)]`. `clippy::type_complexity` on `const` resolves via a type alias, not `#[allow]`.

## Commit scopes

Crate directory as scope: `feat(solver-core): ...`, `feat(solver-py): ...`, `feat(solver-bench): ...`. Bare `solver` only for paired changes spanning crates in one atomic commit.

## Bench workflow

- **Two artifacts, two purposes.** `BASELINE.md` (host-sensitive, criterion, 20% regression budget) gates perf regressions on algorithm PRs. `BENCH_RESULTS.md` (host-stable on feasibility, bake-off) gates feasibility regressions when a backend or fixture changes. Neither runs in CI; algorithm PRs cite the relevant diff. The 20% budget guards hot-loop changes, not one-shot costs (triage criterion deltas by absolute µs on tiny fixtures).
- **Apples-to-apples bench: rerecord `origin/master`'s `BASELINE.md` on the same host the branch is benched on** when any soft-cost axis has landed since the recorded baseline (`supervision_spread`, `soft_pin_miss`, etc). The recorded numbers are stale because new axes add summands; a literal soft-score delta overstates regression. Sequence: stash WIP, `git checkout origin/master`, `mise run bench:record`, snapshot, switch back, rerun on branch, compare. Otherwise pre-existing axis-add PRs masquerade as the branch's regressions. `bench` is NOT in `.github/commit-types.yml`; record baselines as `chore(<scope>): record BASELINE.md ...`.
- **`mise run bench` / `bench:record`** (criterion vs `BASELINE.md`). The bench uses `PRODUCTION_ACTIVE_WEIGHTS`; do not narrow without re-validating feasibility. Three fixtures: `grundschule`, `zweizuegig`, `dreizuegig` (builders in `solver-core/src/test_fixtures.rs`).
- **`mise run bench:bakeoff`** runs the bake-off per `(fixture, backend, seed)` cell against `PRODUCTION_ACTIVE_WEIGHTS` and rewrites `BENCH_RESULTS.md`. Default 60s × 20 seeds × 4 fixtures. **Cells run concurrently by default**, bounded by `--jobs N` (default `std::thread::available_parallelism()`); CP-SAT is locked to `num_search_workers = 1` so cross-cell concurrency does not oversubscribe. On a 16-thread box each phase (pinned or unpinned) runs ~20-30 min so a two-phase pinned + unpinned refresh totals ~40-60 min wall-clock; pass `--jobs 1` to force the historical serial path. Dev-loop downscale via `--budget 5s --seeds 4 --fixtures grundschule`. CP-SAT cells subprocess into `python3 -m klassenzeit_solver.cpsat`; `mise run solver:rebuild` is mandatory pre-flight. The supervisor + cell-child runs each cell in its own process so peak RSS via `getrusage(RUSAGE_SELF)` is honest. ADR 0029, ADR 0034. Writes atomically at end-of-run; do not poll for partial progress. **Smoke-bench runs (`--budget 5s --seeds 4 --fixtures grundschule`) also overwrite `BENCH_RESULTS.md`:** after a smoke run validates a fix, `git checkout BENCH_RESULTS.md` so the production-budget baseline remains canonical. Only production-budget refreshes (60s × 20 seeds × 4 fixtures) should land changes to that file.
- **Tempfile names in `solver-bench` must include `std::process::id()` plus a high-resolution timestamp** (see `tempfile_path` in `solver-bench/src/main.rs`). The supervisor runs cells in parallel processes by default, so a bare `<prefix><nanos><suffix>` filename can collide across sibling cell-child processes that fall in the same nanosecond; the PID disambiguates.
- **New backends register in `solver_core::quality::build_backend_objectives`** (renderer panics on `None`). Two-commit shape: register in `solver-core` first, then wire the `BenchBackend` variant in `solver-bench`.
- **Bench markdown-row substring assertions anchor on cell delimiters** (`| lahc_kempe |`), not bare labels. New H2 sections go between `write_title_and_intro` and `write_table_header`; placing one after the header splits the table.
- **Production-default ADRs (0031, 0032, 0037) reason from per-component vectors in BENCH_RESULTS.md,** not the collapsed `Soft score` scalar. The aggregate score is the only signal for the canonical axes the bench markdown does not render as standalone columns (subject_pref, per-class-max); a consistent direction across all fixtures is signal.
- **Production refresh shortcut.** When the verdict is decidable from the post-everything pinned cross-section plus a 5s × 1-seed smoke (hard gate invariant under sample widening, soft-score tiebreak consistent), cite both data sources in the ADR and file a P2 follow-up rather than burning 10-12 h.
- **No-change refresh ratification: amend in place, do not burn an ADR number.** When a production refresh confirms an existing production-default ADR's verdict (survivor set unchanged and the soft-score / per-component / stddev tiebreak chain still lands on the same backend, even if aggregate sums flip inside the host-sensitivity noise band), append a `## Ratification (YYYY-MM-DD refresh)` section to the parent ADR rather than open a new one. The parent's `Status: Accepted` and `Date:` stay; the new section captures the refreshed tables, per-component vectors, and rationale for holding so the next refresh's reasoner does not re-derive the verdict from `BENCH_RESULTS.md`. Test: "would a new ADR be substantively different from a section in the existing one?" If no, amend.
- **Schedule-quality predicates in `solver-bench/src/quality.rs` are `QualityPredicates`** (renamed from `QualityReport` in item 50). Pure functions over `&Problem` + `&Solution`; cross-language parity with the Python evaluator is intentionally not a contract. Thresholds in `QUALITY_*` constants match the Python test verbatim.
- **`solver_core::quality_report` is the backend-neutral cost-vector breakdown.** Contract: `quality_report.weighted_score == score_solution(problem, placements, weights)`. New soft-cost axes must extend `QualityReport` with a raw-count field and update `weighted_score`'s aggregation. `score_solution` stays in the hot path; `quality_report` is cold-path only.
- **Bench `Quality (pass / 5)` does NOT predict integration-test pass on the solver-driven teacher path.** Bench cells pin teachers; integration tests solve a strictly larger search space. Gate xfail-removal items on a 20-iteration flake-loop at production wall-clock, not bench quality. The five predicates are worst spread, worst home-room ratio, total interior gaps, late-period ratio, and Klassenlehrer share (`kl_share_med`, fraction of `(class, subject)` pairs whose single teacher equals the class's `class_teacher_id`; cells with no Klassenlehrer set render `-` and count as pass). Thresholds in `QUALITY_*` constants in `solver-bench/src/quality.rs`; renderer footer says "rightmost six" (5 predicates + composite). **Unit tests on FFD or LAHC comparators (e.g. `ffd_order` ordering invariants) also do not predict the flake-loop on quality-predicate-adjacent fixtures.** A clean RED→GREEN comparator test + clean `mise run test:rust` + clean `mise run test:py` can co-exist with an 18/20 `test_grundschule_schedule_meets_quality_bar` flake-loop because the comparator change can perturb a different quality axis (e.g. `interior_gap` while targeting `home_room`). The 20-iter flake-loop is the validator for any structural FFD/LAHC ordering change too, not only for xfail-removal items.
- **`Problem.room_subject_suitabilities` is keyed by ROOM, not by subject.** A row `(room=X, subject=Y)` means "room X is suitable for subject Y ONLY"; rooms WITHOUT any entries default-suit ALL subjects (see `Indexed::room_suits_subject`). Test-fixture gotcha: to "make subject S suitable only in room R", do NOT add `(room=R, subject=S)`; that restricts room R, but every other room (no entries) still suits S. The correct shape is to add an entry on each OTHER room listing the subjects it DOES suit (excluding S), so those rooms become subject-restricted; or to add `(room=X, subject=T)` for every non-target room with a placeholder T so they stop default-suiting S.
- **`--teacher-pins=on|off`** toggles bench-side pinning; `off` calls `unpin_teachers_in_problem`. Two-invocation production refresh for the pinned + unpinned cross-section: `--teacher-pins on` then `... off --append`, sequential (host-sensitive on wall-clock and peak RSS).
- **Production-budget `bench:bakeoff` is supervised via `run_in_background` + a persistent `Monitor`** tailing the log for `cell done|panic|thread .* panicked|FATAL|Killed|Error`. Pre-flight: `uptime` + `ps -eo pcpu,pmem,etime,comm --sort=-pcpu | head -10` to catch stuck siblings.
- **Production-budget `bench:bakeoff` must launch via `mise run bench:bakeoff` (or `uv run cargo run -p solver-bench --release -- ...`), NOT bare `cargo run -p solver-bench`.** The CP-SAT cells subprocess into `python3 -m klassenzeit_solver.cpsat`; the bare-cargo invocation uses the system `python3` (from PATH) which has no `klassenzeit_solver` wheel installed, and every CP-SAT cell silently records `0/20 feasibility` with `cpsat subprocess non-zero exit (seed=N): ... Error while finding module specification for 'klassenzeit_solver.cpsat' (ModuleNotFoundError)` on the bench log. LAHC cells are unaffected (they're pure Rust), so a bare-cargo bench can look superficially fine on the LAHC cross-section while overwriting `BENCH_RESULTS.md` with corrupted CP-SAT rows. The mise task aliases to `uv run cargo run -p solver-bench --release --`, which activates the project `.venv` populated by `mise run solver:rebuild`. Same shape applies to any future bench whose cell-children invoke Python.
- **Bench panic rows naming a post-condition validator surface bugs in newly-added LAHC move helpers that unit tests pass in isolation.** Panic message shape (cell-child stderr): `solve: Input("room hopping for class ... day N subject ...: rooms RoomId(a) and RoomId(b)")` (from `validate_no_room_hopping`); `solve: Input("double-booking: <class|teacher> ... at time-block ...: lessons ... and ...")` (from `validate_no_double_booking`). Both fire at `solver-bench/src/main.rs`'s `.expect("solve")` after `solve_with_config_stats` returns `Err`. Fix sites are the rules above (new cross-day move helpers must consult `state.locked_room` at every destination triple; new same-day room-only moves must walk siblings on `(class, day, subject)`). The bench's production-budget × 20 seeds × 4 fixtures × 2 phases coverage is the canary because LAHC's accepted-move sequence is seed-dependent: a clean unit test on the move helper in isolation + clean `mise run test:rust` + clean `mise run test:py` can co-exist with 8 bench-cell panics across `lock_in` + `dreizuegig` × LAHC variants (item 88 / ADR 0050 / #300 is the 2026-05-20 instance). Smoke bench (`--budget 5s --seeds 4`) is structurally weaker for this shape: the bad accepted-move sequence may not occur within 5s. Validate any new LAHC move helper with a production-budget refresh of the pinned + unpinned cross-section before closing the implementing item.
- **`PRODUCTION_ACTIVE_WEIGHTS` rebalance shifts the soft-score column baseline across all cells.** When the const literal in `solver-core/src/types.rs:PRODUCTION_ACTIVE_WEIGHTS` changes (e.g. item 87 raised `interior_gap` weight, 2026-05-15→2026-05-20), the `Soft score (median, feasible)` column shifts even on cells where every per-component column held flat (grundschule LAHC 32→62 with gaps=0 and day_balance=2 unchanged). Cross-period BENCH_RESULTS.md soft-column comparison is NOT apples-to-apples across a weight-rebalance commit; per-component columns remain comparable. Algorithm PRs reading the soft scalar against a prior BENCH_RESULTS.md must check the `PRODUCTION_ACTIVE_WEIGHTS` diff first, or compare per-component columns directly.
