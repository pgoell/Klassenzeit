## Context

ADR 0029 records the four-candidate bake-off framework. Sprint 1 (PR #175) shipped Path A (same-room-aware FFD ordering), the `solver-bench` workspace member, and the first `BENCH_RESULTS.md` snapshot showing `lahc` reliably feasible across the demo Grundschule, zweizuegig, dreizuegig, and lock-in fixtures. Sprint 2's job is to add a stronger LAHC move (R&R) that diversifies away from FFD-induced lock-ins on harder fixtures Sprints 3 and 4 will exercise (Beyond-Grundschule program brings Gymnasium Sek I, Differenzierung, Gesamtschule fixtures next).

LAHC's existing single-cell Change move polishes accepted placements one cell at a time. It cannot escape a region where every Change move is infeasible (the room picker rejects), nor can it re-place an unplaced lesson (LAHC moves rows that exist; an unplaced lesson never enters the placements vector). R&R fills that gap: pick K placements, undo them, re-run the FFD placer on the resulting freer search space.

Anchor research: `docs/research/2026-04-04-solver-algorithm-selection.md`. Anchor sprint: `docs/superpowers/OPEN_THINGS.md` "Sprint 2: Ruin-and-recreate as a LAHC move", item 6.

## R&R move semantics

### Per-iteration scheduling

The LAHC loop in `lahc::run` becomes:

```text
loop while iter < max_iter && elapsed < deadline:
    if rr_period.map_or(false, |n| iter % n == 0):
        rr_attempt(rr_rng, ...)            # diversification
    else:
        change_attempt(change_rng, ...)    # polish
    iter += 1
    lahc_list[iter % LEN] = current_score
```

`rr_period == Some(25)` (the bake-off backend's setting) gives 1 R&R attempt per 25 iterations. The Change-move RNG remains untouched on R&R iterations; it is the diversification step that should not perturb the polish-step sequence.

### Ruin step

For one R&R attempt:

1. Build a list of *block-anchor* placements: each placement that is the first hour (lowest `tb.position` on its `day`) of a (lesson, day) block. Skip placements whose lesson is in `pinned`. Skip placements whose lesson has a `lesson_group_id`.
2. Draw `K = min(RR_K, anchors.len())` anchors from the list without replacement, using the R&R-dedicated `SmallRng`. Sampling primitive: shuffle a candidate index vector via `SliceRandom::shuffle`, take the first K.
3. For each chosen anchor, identify the full block (all `n = lesson.preferred_block_size` consecutive `placements[i]` rows on the same day). Remove those rows from `placements`, decrement bookkeeping per row:
   - `used_teacher` removes `(teacher_id, time_block_id)`.
   - For each `class_id` in the lesson, `used_class` removes `(class_id, time_block_id)`. `class_positions[(class_id, day)]` removes the block's `position`.
   - `used_room` removes `(room_id, time_block_id)`.
   - `teacher_positions[(teacher_id, day)]` removes the block's `position`.
   - `hours_by_teacher[teacher_id]` decrements by 1 (per row).
   - `locked_room[(class_id, day, subject_id)]` ref-count decrements by 1; remove the entry when count reaches 0.

After the ruin loop, `placements.len()` has dropped by the total ruined hour count (sum of N over chosen blocks), and the bookkeeping is consistent with the ruined state.

Snapshot the ruined state's `(soft_score, hard_violation_count)` for the acceptance gate.

### Recreate step

For each ruined block (in the order the anchors were chosen, which is deterministic given the R&R RNG sequence), call `place::try_place_block(problem, lesson, n, ...)` against the ruined bookkeeping. On success, the bookkeeping mutations match what FFD does on a fresh placement; on failure, the lesson is left unplaced for now and recreate continues to the next ruined lesson.

Track `failed_recreates: usize` during recreate. Compute `new_soft_score` from the running `current_score` mutated by `try_place_block` (which already updates `state.soft_score` for greedy callers; see Q5 implementation note about adapting that path for LAHC's running score).

**v1 scope: ruined-only recreate.** R&R does not attempt to rescue FFD-unplaced lessons (those listed in `solution.violations` with kinds `NoFreeTimeBlock` / `NoSuitableRoom` / `TeacherOverCapacity`). OPEN_THINGS item 6 mentions `"plus any currently-unplaced lessons"` as a stretch; deferring it to a follow-up under "After bake-off" keeps the v1 scope reviewable and the rollback story simple. If Sprint 2 BENCH data shows feasibility cells where `lahc_rr` ties `lahc` despite available diversification headroom, the rescue path becomes the first follow-up.

### Acceptance gate

```text
if failed_recreates > 0 {
    REJECT          // R&R produced violations the prior state didn't have
} else {
    let prior   = lahc_list[iter % LEN];
    let lahc_ok = new_soft_score <= cur_soft_score || new_soft_score <= prior;
    accept = lahc_ok
}
```

The `failed_recreates > 0` branch is the asymmetric guard: it keeps R&R from regressing feasibility. With v1's ruined-only scope, R&R cannot increase the violation count beyond rejecting itself, so the running `solution.violations` Vec stays untouched (no need to thread `&mut Vec<Violation>` through `lahc::run`).

If `accept`, the new state is committed (placements + bookkeeping kept, `current_score` updated). If `!accept`, the move rolls back: every ruined block is re-placed at its original `(time_block_id, room_id)` and the bookkeeping is restored. Implementation: snapshot the ruined placements *and the original bookkeeping mutations* before recreate; on reject, drop any newly-recreated rows + replay the snapshot.

### Determinism contract

- The Change-move RNG (`SmallRng` seeded from `config.seed`) is consumed exactly twice per Change iteration as today. Iterations where R&R fires do not advance this RNG.
- The R&R RNG (`SmallRng` seeded from `config.seed.wrapping_add(1)`) advances by an unspecified number of draws per R&R attempt. The number depends on K, the shuffle implementation, and the recreate primitive's room scan. Determinism is preserved because (i) the seed is fixed by `config.seed`, (ii) the RNG is not shared with any other path, (iii) `try_place_block` is deterministic on its input bookkeeping.
- LAHC iteration counter `iter` advances by 1 per attempt regardless of whether the attempt was R&R or Change, so deadline accounting and `lahc_list[iter % LEN]` indexing are unchanged.

The new property test `lahc_rr_deterministic_under_seed_and_iter_cap` calls `solve_with_config(p, &cfg)` twice with `lahc_rr_period: Some(25)` and asserts the two solutions are byte-equal.

## Public API surface

### `SolveConfig` change

```rust
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct SolveConfig {
    pub deadline: Option<Duration>,
    pub seed: u64,
    pub weights: ConstraintWeights,
    pub max_iterations: Option<u64>,
    /// Period for the ruin-and-recreate LAHC move. `None` (default) disables
    /// R&R; the LAHC loop runs Change-only. `Some(n)` triggers an R&R attempt
    /// every nth iteration, with Change attempts on the other (n-1)/n. The
    /// bake-off bench's `lahc_rr` backend sets this to `Some(25)`. Production
    /// callers leave this `None`; the active default in `solve()` is
    /// unchanged.
    pub lahc_rr_period: Option<u32>,
}
```

`Default::default()` preserves backward compatibility (`None` = disabled).

### `BenchBackend` change

```rust
enum BenchBackend {
    Lahc,
    LahcRr,
}

impl BenchBackend {
    fn label(self) -> &'static str {
        match self {
            BenchBackend::Lahc => "lahc",
            BenchBackend::LahcRr => "lahc_rr",
        }
    }
}

const BACKENDS: &[BenchBackend] = &[BenchBackend::Lahc, BenchBackend::LahcRr];
```

`run_cell` extends with a `backend` arm so `LahcRr` builds `SolveConfig { lahc_rr_period: Some(25), ..common }`.

### Solver-py / backend impact

None. `solve_json` and `solve_json_with_config` continue to call `solve()` with the active default config (where `lahc_rr_period == None`). The R&R move is bench-only until Sprint 4 introduces the public `SolverBackend` enum and the env-var dispatch wires it through.

## Risks

- **Placer extraction balloons.** Mitigation: skip the refactor commit, use the in-place `pub(crate)` function via a `use` statement.
- **`lahc_rr` regresses any cell on `BENCH_RESULTS.md` vs `lahc`.** Treat as bench data (the bake-off's job). Cite the regression in the PR body; Sprint 3's brainstorm decides whether to retune the period or K.
- **Block-ruin lock-counting bug on partial ruin of a same-room triple.** Mitigated by unit tests `rr_block_ruin_keeps_locked_room_when_partial` and `rr_block_ruin_decrements_locked_room_to_zero_when_last_placement_leaves_triple` (Q13(c)).
- **R&R RNG split breaks an adjacent test.** Mitigated by running the full Rust suite (`cargo nextest run --workspace`) before each commit. The existing Change-move determinism property test catches Change-RNG drift.
