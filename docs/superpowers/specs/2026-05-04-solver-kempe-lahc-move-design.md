## Context

ADR 0029 records the four-candidate bake-off framework. Sprint 1 (PR #175) shipped Path A (same-room-aware FFD ordering), the `solver-bench` workspace member, and the first `BENCH_RESULTS.md` snapshot showing `lahc` reliably feasible across the four fixtures. Sprint 2 (PR #177) shipped R&R as a third LAHC move type with a separate RNG seeded from `seed.wrapping_add(1)`, an asymmetric acceptance gate, and the `lahc_rr` bench column. Sprint 3's job is to add Kempe chain swaps as a fourth LAHC move type, composed atop R&R, and to ship the head-to-head bench column.

LAHC's existing Change move polishes one cell at a time. R&R diversifies by ruining K block-anchors and re-running FFD. Neither move can resolve a feasibility deadlock where two blocks at slots T1, T2 each want the slot the other holds: Change can only move one at a time (and the destination is occupied), R&R re-places the ruined blocks via FFD which would just hit the same deadlock. Kempe chain swap fills that gap: pick block B1 at slot T1, propose a swap to slot T2, BFS the conflict graph to find every block that must also move to make the swap consistent, apply atomically.

## Kempe move semantics

### Per-iteration scheduling

The LAHC loop in `lahc::run` becomes:

```text
loop while iter < max_iter && elapsed < deadline:
    is_rr_iter    = rr_period.is_some_and(|n| n > 0 && (iter as u32) % n == 0)
    is_kempe_iter = kempe_period.is_some_and(|n| n > 0 && (iter as u32) % n == 0)
                    && !is_rr_iter           // R&R wins on shared iter

    if is_rr_iter:
        rr_attempt(rr_rng, ...)              # diversification
    else if is_kempe_iter:
        kempe_attempt(kempe_rng, ...)        # cascade-resolving swap
    else:
        change_attempt(change_rng, ...)      # polish

    iter += 1
    lahc_list[iter % LEN] = current_score
```

`rr_period == Some(25)` and `kempe_period == Some(23)` (the bake-off `lahc_rr_kempe` settings) gives ~4% R&R / ~4.3% Kempe / ~92% Change. The two periods are coprime (lcm = 575), so collisions are rare; on the rare shared iter, R&R wins and Kempe gets the next free slot. The Change-move RNG and the R&R-move RNG remain untouched on Kempe iterations; symmetrically the Kempe RNG is untouched on Change and R&R iterations.

### Seed step

For one Kempe attempt:

1. Build a list of *block-anchor* placements (one tuple `(LessonId, day_of_week)` per block, as `rr_collect_anchors` does today). Skip placements whose lesson is in `pinned`. Skip placements whose lesson has a `lesson_group_id`.
2. Draw an anchor index uniformly from the K-RNG; let B1 be the chosen anchor with current day D1 and start position P1.
3. Draw a target day D2 from the K-RNG. Resampling: pick from `0..7` excluding D1 (one extra modulo arithmetic step keeps the draw count predictable; uses one `random_range` call).
4. Verify the target window: positions P1..P1+N-1 must be valid `time_block` ids on day D2 (where N = `B1.lesson.preferred_block_size`). If any position is missing on D2 (e.g., D2 has fewer periods than D1 in the week-scheme), ABORT this Kempe attempt.

### Chain construction (BFS)

Initialize:

- `chain: HashMap<LessonId, u8>` mapping each chain member's lesson-id to its **destination day**. Insert `B1 -> D2`.
- `frontier: VecDeque<LessonId>` initialized with `[B1.lesson_id]`.
- `frontier_seen: HashSet<LessonId>` initialized with `{B1.lesson_id}` to prevent re-adding.

Iterate:

```text
while let Some(lesson_id) = frontier.pop_front():
    let dest_day = chain[lesson_id]
    let lesson   = lesson_lookup[lesson_id]
    let dest_window_tbs = time_blocks at (dest_day, P1..P1+N_lesson-1)

    // Find every existing placement at the destination window that conflicts
    // with `lesson`. "Conflict" = shares teacher OR shares at least one class.
    let mut new_neighbours: Vec<LessonId> = Vec::new()
    for tb in dest_window_tbs:
        for placement at tb (excluding chain members already moving away from dest_day):
            let other = lesson_lookup[placement.lesson_id]
            if pinned.contains(&placement.lesson_id) || other.lesson_group_id.is_some():
                ABORT (chain hit pinned or group)
            if other.teacher_id == lesson.teacher_id || classes overlap:
                if !frontier_seen.contains(&other.id):
                    new_neighbours.push(other.id)
                    frontier_seen.insert(other.id)

    // Determinism: sort new neighbours before extending the frontier so HashSet
    // iteration order does not leak into the chain shape.
    new_neighbours.sort_unstable_by_key(|id| id.0)

    for neighbour_id in new_neighbours:
        let neighbour_dest = if dest_day == D2 { D1 } else { D2 }
        chain.insert(neighbour_id, neighbour_dest)
        frontier.push_back(neighbour_id)

        if chain.len() > KEMPE_MAX_CHAIN:
            ABORT (chain over bound)

    // Window-contiguity check for each new neighbour: positions P1..P1+N-1 of
    // `neighbour.lesson` must exist on `neighbour_dest` day. Otherwise ABORT.
```

After BFS terminates, `chain` holds every block that participates in the swap, with each block's destination day. Chain length is bounded by `KEMPE_MAX_CHAIN`.

The "destination day" assignment is bipartite: each chain member's destination is the day **opposite** the day a chain neighbour caused it to be added. This ensures every chain member moves D1 → D2 or D2 → D1 (never stays in place; that is the "swap" property).

### Apply step (with rollback snapshot)

For each chain member:

1. Snapshot the current placements (the full N-block) into a `BlockSnapshot { rows: Vec<Placement> }` per `solver-core/src/lahc.rs` L561 (reuse the type).
2. Remove the N rows from `placements` and decrement `state` bookkeeping per row (mirror `rr_ruin_block` per `lahc.rs` L570).
3. Decrement the same-room lock at `(class, source_day, subject)` for every member of `lesson.school_class_ids`.

After every chain member is removed:

For each chain member, in deterministic order (by `LessonId.0` ascending):

4. Pick a feasible room at the destination window. **Reuse-old-room preference**: try `original_room_id` first; fall back to lowest-id room satisfying:
   - `idx.room_suits_subject(room.id, lesson.subject_id)`
   - For each TB in the destination window: `!state.used_room.contains(&(room.id, tb.id))` AND `!idx.room_blocked(room.id, tb.id)`
   - **Same-room lock at destination**: if `state.locked_room.get(&(class, dest_day, subject))` exists, only that room is feasible.
5. If no feasible room, ABORT (rollback below).
6. Insert the N rows at the destination window with the chosen room. Increment all bookkeeping (mirror `rr_recreate`'s `try_place_block` call but specialized to the known window):
   - `placements.push(Placement { lesson_id, time_block_id: dest_tb.id, room_id })` for each TB.
   - `used_teacher.insert((teacher, dest_tb.id))` per TB.
   - `used_class.insert((class, dest_tb.id))` per TB per member class.
   - `used_room.insert((room_id, dest_tb.id))` per TB.
   - `class_positions[(class, dest_day)].insert_sorted(position)` per member class per TB position.
   - `teacher_positions[(teacher, dest_day)].insert_sorted(position)` per TB position.
   - `hours_by_teacher[teacher] += 1` per TB.
   - `locked_room[(class, dest_day, subject)]` ref-count `+= 1` per member class per TB. Initialise to `(room_id, 0)` if absent.
7. Update `state.soft_score` by computing the per-chain-member delta: the day part changes (gap-count delta on `class_positions` and `teacher_positions` for source and dest days, plus `class_day_balance`) but the position part is unchanged so subject_pref stays put.

### Acceptance gate

```text
if any abort during chain construction OR any abort during apply:
    rollback to pre-attempt snapshot
    return REJECT
let new_score = state.soft_score
let prior    = lahc_list[iter % LEN]
let lahc_ok  = new_score <= pre_score || new_score <= prior
if !lahc_ok:
    rollback to pre-attempt snapshot
    return REJECT
return ACCEPT
```

The asymmetric `any abort` branch keeps Kempe from regressing feasibility (rollback restores the pre-attempt state byte-for-byte). With the chain-construction guarantees (BFS walks all teacher / class conflicts), the post-apply state has no teacher / class double-bookings on the swapped windows. Room conflicts are caught at apply-time via the room scan.

### Rollback

Rollback shape mirrors R&R's `rr_rollback` (per `lahc.rs` L814):

For each chain member that was successfully re-placed (in reverse insertion order):

1. Remove every newly-inserted row from `placements`.
2. Decrement every newly-incremented bookkeeping entry (used_teacher, used_class, used_room, class_positions, teacher_positions, hours_by_teacher, locked_room).

Then, for each `BlockSnapshot` (in reverse collection order):

3. Re-insert each snapshot row into `placements` and re-increment the bookkeeping (mirror `replay_placement` per `lahc.rs` L842).

Restore `state.soft_score` to the pre-attempt value (saved at the top of `kempe_attempt`).

### Determinism contract

- The Change-move RNG (`SmallRng` seeded from `config.seed`) is consumed exactly twice per Change iteration as today. Iterations where R&R or Kempe fire do not advance this RNG.
- The R&R RNG (`SmallRng` seeded from `config.seed.wrapping_add(1)`) advances by an unspecified number of draws per R&R attempt. Iterations where Change or Kempe fire do not advance this RNG.
- The Kempe RNG (`SmallRng` seeded from `config.seed.wrapping_add(2)`) advances by an unspecified number of draws per Kempe attempt (one for the anchor index, one for the target day). Iterations where Change or R&R fire do not advance this RNG.
- The chain BFS pops the frontier in deterministic order: `VecDeque` plus `sort_unstable_by_key(|id| id.0)` on the new neighbours before extending the frontier. Without the sort, `HashSet<LessonId>` iteration would leak `RandomState` into the chain shape.
- LAHC iteration counter `iter` advances by 1 per attempt regardless of whether the attempt was Change, R&R, or Kempe, so deadline accounting and `lahc_list[iter % LEN]` indexing are unchanged.

The new property test `lahc_kempe_deterministic_under_seed_and_iter_cap` calls `solve_with_config(p, &cfg)` twice with `lahc_kempe_period: Some(5)` and asserts byte-equal solutions.

```rust
pub struct SolveConfig {
    pub deadline: Option<Duration>,
    pub seed: u64,
    pub weights: ConstraintWeights,
    pub max_iterations: Option<u64>,
    /// Period for the ruin-and-recreate LAHC move. `None` (default) disables

    /// Period for the Kempe-chain LAHC move. `None` (default) disables Kempe;

```

`Default::default()` preserves backward compatibility (`None` = both move types disabled).

## Risks

- **Chain BFS becomes non-deterministic via HashSet iteration.** Mitigated by sorting new neighbours by `LessonId.0` before extending the frontier (determinism contract bullet 4). Caught by `lahc_kempe_deterministic_under_seed_and_iter_cap` property test.
- **Apply-time room collision causes silent bookkeeping drift.** Mitigated by the asymmetric acceptance gate and the `BlockSnapshot`-based rollback (mirrors R&R's shape). Caught by `kempe_chain_rollback_restores_state_on_room_failure` unit test.
- **Kempe regresses any cell on `BENCH_RESULTS.md` vs `lahc_rr`.** Treat as bench data (the bake-off's job). Cite the regression in the PR body; Sprint 4's brainstorm decides whether to retune the depth, the period, or to escalate room-as-chain-edge.
- **K-RNG split breaks an adjacent property test silently.** Mitigated by running the full Rust suite (`cargo nextest run --workspace`) before each commit. Existing R&R determinism property test catches R&R-RNG drift; existing Change determinism property test catches Change-RNG drift. New K-RNG property test catches K-RNG drift.
- **Bench regen for Sprint 3 takes ~240 min wall-clock.** Mitigated by running locally during dev with `--budget 5s --seeds 4` for fast iteration; the final full-budget run lands in commit 3.
- **Lesson-group skip causes Kempe to be inert on dreizügige.** The dreizügige fixture's per-Jahrgang Religion trios are lesson-grouped (3 × 4 = 12 lessons of 102 placements ≈ 12%); 88% of placements remain Kempe-eligible. If the bench shows Kempe stalling specifically on dreizügige, the lesson-group co-swap follow-up becomes priority.
