# Kempe-chain LAHC move implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to dispatch each task to a fresh subagent. Tasks share state (every task touches `solver-core` or its bench), so dispatch sequentially, not in parallel. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Kempe chain swaps as a fourth LAHC move type, ship the `lahc_rr_kempe` bake-off bench column, refresh `BENCH_RESULTS.md` with the head-to-head against `lahc` and `lahc_rr`.

**Architecture:** Two-day same-position block-anchor swap. BFS over a teacher+class conflict graph (rooms handled at apply-time). Block-aware (Doppelstunden swap atomically). Pin-skip and lesson-group-skip at chain-collect time. Chain depth bounded at `KEMPE_MAX_CHAIN = 8`. Three LAHC RNGs (Change `seed`, R&R `seed.wrapping_add(1)`, Kempe `seed.wrapping_add(2)`); each consumed only on its own iteration type. Asymmetric acceptance gate: any abort during chain construction or apply rolls back; otherwise standard LAHC criterion on `state.soft_score`.

**Tech Stack:** Rust 2021, `solver-core` library + `solver-bench` binary, `proptest` for property tests, `cargo nextest` for unit tests, `mise run bench:bakeoff` for the bench refresh.

**Spec:** `docs/superpowers/specs/2026-05-04-solver-kempe-lahc-move-design.md`. Read it before starting any task. Anchor: ADR 0029 + OPEN_THINGS Sprint 3 item 7.

- [ ] **Step 1.5: Implement `kempe_attempt` end-to-end.** Replace the `unimplemented!()` with the full algorithm per the spec's "Kempe move semantics" section. Structure inside `kempe_attempt`:

  1. **Seed pick:** collect block-anchors via `rr_collect_anchors` (reuse the R&R helper; identical eligibility rules). If empty, return false.
  2. Pick anchor index uniformly via `kempe_rng.random_range(0..anchors.len())`. Let B1 = `anchors[picked]`. Read its current day D1 from the placement's TB. Pick D2 from `0..7` excluding D1 via `kempe_rng.random_range(0..6)` then bump by 1 if `>= D1`.
  3. **Window verification:** read N from `B1.lesson.preferred_block_size` and the start position P1 from B1's anchor placement. For each k in 0..N, check that a TB with `(day_of_week=D2, position=P1+k)` exists in `tb_lookup`. If any missing, return false.
  4. **Chain BFS:** initialise `chain: HashMap<LessonId, u8>` with `B1.lesson_id -> D2`, `frontier: VecDeque<LessonId>` with `[B1.lesson_id]`, `frontier_seen: HashSet<LessonId>` with `{B1.lesson_id}`. Loop while frontier non-empty: pop, look up dest_day from chain, walk every placement at the dest window, find conflicts (shared teacher OR shared class member) with the popped lesson. For each conflicting placement: if pinned or group-tagged, return false (chain hit a non-eligible lesson). Otherwise add to a `new_neighbours: Vec<LessonId>`. After the per-window walk, sort `new_neighbours` by `LessonId.0` ascending (determinism), then for each: insert `(neighbour_id, opposite_day)` into chain, push to frontier, check `chain.len() > KEMPE_MAX_CHAIN` and return false if exceeded. Also verify each new neighbour's window exists on its destination day; return false if missing.
  5. **Snapshot + remove:** for each chain member in deterministic order (sort by `LessonId.0`), find the block's anchor placement index, call a `kempe_ruin_block` helper that mirrors `rr_ruin_block` (returning a `BlockSnapshot`). Collect snapshots into `Vec<(LessonId, u8 /* source_day */, BlockSnapshot)>`.
  6. **Apply:** for each chain member in the same deterministic order, pick a destination room (try the snapshot's original `room_id` first; fall back to lowest-id feasible per the spec's apply step). If no feasible room, set `failed = true` and break. Otherwise re-insert N placements at `(dest_day, P1..P1+N-1)` with the chosen room, update bookkeeping mirror of `replay_placement`. Update `state.soft_score` by computing the per-member soft-score delta (see spec's "Apply step" item 7; the existing `score_after_change_move` and `partition_delta` helpers do the gap-count math).
  7. **Acceptance gate:** if `failed` OR the LAHC criterion `new_score <= pre_score || new_score <= prior` rejects, call `kempe_rollback` and return false. Otherwise return true.

  Snapshot the pre-attempt `state.soft_score` at the top of the function so rollback can restore it.

- [ ] **Step 1.6: Implement `kempe_rollback`.** Mirrors `rr_rollback` (per `lahc.rs` L814):

```rust
fn kempe_rollback(
    recreated_in_order: &[LessonId],
    snapshots: &[(LessonId, u8, BlockSnapshot)],
    lesson_lookup: &HashMap<LessonId, &Lesson>,
    tb_lookup: &HashMap<TimeBlockId, &TimeBlock>,
    placements: &mut Vec<Placement>,
    state: &mut crate::solve::GreedyState,
) {
    for lesson_id in recreated_in_order.iter().rev() {
        let lesson = lesson_lookup.get(lesson_id).expect("recreated lesson resolves");
        if let Some(idx) = placements.iter().position(|p| p.lesson_id == *lesson_id) {
            rr_ruin_block(idx, lesson, tb_lookup, placements, state);
        }
    }
    for (lesson_id, _src_day, snapshot) in snapshots.iter().rev() {
        let lesson = lesson_lookup.get(lesson_id).expect("snapshot lesson resolves");
        for row in snapshot.rows.iter().rev() {
            replay_placement(lesson, row, tb_lookup, placements, state);
        }
    }
}
```

`replay_placement` and `rr_ruin_block` are reused as-is from the R&R section.
