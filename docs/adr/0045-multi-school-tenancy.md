# 0045: Multi-school tenancy (tracer bullet)

## Status

Accepted (2026-05-16).

## Context

`OPEN_THINGS.md` item 10 captures the multi-school tenancy program: schools table, `school_id` FK on every aggregate root, query scoping in every route, seed scripts, E2E tests. Required before customer school #2 onboards. The full program is too large for a single reviewable PR; this ADR captures the tenancy decisions made by the tracer-bullet PR that covers ONE aggregate (`Room`) end-to-end.

## Decision

1. **Tenancy primary key.** `schools.id` is a UUID generated by Postgres `gen_random_uuid()`. The default-school row uses the canonical UUID `00000000-0000-0000-0000-000000000001` so migrations and tests can reference a fixed id.
2. **User-school relationship.** Single-column `users.school_id` (1:1). M:N membership via a `user_school_memberships` join table is deferred to a follow-up sub-item; the migration path is to copy `users.school_id` into the new join table and drop the column.
3. **Aggregate-root FKs.** Every tenanted aggregate gets a NOT NULL `school_id` FK to `schools.id`. The tracer covers `rooms` only; the remaining aggregates (`SchoolClass`, `Teacher`, `Subject`, `Stundentafel`, `WeekScheme`, `TimeBlock`, `Lesson`, `LessonSchoolClass`, `SupervisionAssignment`, `ScheduledLesson`) ship as follow-up sub-items. `RoomSubjectSuitability` and `RoomAvailability` inherit tenancy transitively through `room_id` and need no own column.
4. **Per-school uniqueness.** Single-column `UNIQUE(name)` and `UNIQUE(short_name)` constraints on tenanted tables become composite `UNIQUE(school_id, name)` / `UNIQUE(school_id, short_name)`. Each school sees its own namespace.
5. **Query scoping.** Route handlers and non-CRUD readers add `.where(<Aggregate>.school_id == current_user.school_id)`. Cross-school access returns 404, not 403, to prevent existence leakage.
6. **Auth surface.** `MeResponse` carries `school_id` and `school_name`. No JWT changes (session-cookie auth; the loaded `User` already exposes `school_id`).
7. **Migration backfill.** Migrations adding a tenanted column add it nullable, backfill every existing row to the default school, then set NOT NULL. Operators rename the default school via `UPDATE schools SET name = '<name>' WHERE id = '00000000-0000-0000-0000-000000000001'`.
8. **No transitional server-side defaults.** Tracer's first commit added a `server_default` on `users.school_id` / `rooms.school_id` so unrelated code paths kept working; that default was removed in the same PR (commit 2) after every reader and writer is school-scoped. Any future code that forgets to set `school_id` fails loudly with a NOT NULL violation rather than silently landing in the default tenant.

## Consequences

- Per-aggregate follow-up PRs are mechanical: add FK + migration + scope every reader. The pattern is proven by the Room tracer.
- The solver model sees a mix of scoped (rooms) and global (everything else) data until each aggregate is tenanted. In single-school production this is invisible because there is one school. A second school cannot enter the DB through any user-facing endpoint until the school CRUD follow-up (10b) ships.
- Multi-membership and a school-picker UI are deferred to follow-up sub-items; today, every user belongs to exactly one school.

## Alternatives considered

- **All-in-one PR**: too large; not reviewable.
- **Multi-membership join table from day one**: bigger surface (active-school session field, school-picker UI) without near-term value; one user per school is sufficient until customer #2.
- **403 instead of 404 on cross-school access**: leaks the existence of other-school rows; 404 is the safer default.
