## Project-specific rules

1. **Solver-binding rebuild discipline.** Subagents that run Python or backend integration tests consuming `klassenzeit_solver` AFTER an earlier task touched `solver/solver-core/` or `solver/solver-py/` MUST include `mise run solver:rebuild` as an explicit step before pytest, or the binding is stale and the agent observes phantom wire-format bugs. Same shape applies to `mise run fe:types` after backend Pydantic schema changes if the next task touches frontend types.
2. **OPEN_THINGS.md hygiene.** (a) When an item ships, DELETE it; no shipped-on annotation. PR description and git log are canonical. (b) When closing the last item in an active-sprint program, promote the next paused sprint to active and DELETE the closed sprint header. Open quality and tuning items from the closed sprint move to a `## Open <topic> follow-ups` section. (c) Closing an item that takes an ADR number: `grep -n 'ADR <NNNN>' docs/OPEN_THINGS.md` and refresh every stale reference in the same commit. (d) Closing item N: `grep -n 'item N' docs/OPEN_THINGS.md` and refresh forward-looking references in other active items' bodies. Past-tense narrative references inside another item's `**shipped**` paragraph are historical and stay. (e) When closing the last entry under an `### <Phase>` header inside an active sprint, DELETE the empty header alongside. (f) P2 conditional items framed "promote / add X only if Y shows up in a refresh" may have unfireable triggers: hard-constraint predicates enforced by `solver-core/src/validate.rs`'s validator septet surface as `Err(Error::Input)` (panic rows in BENCH_RESULTS.md), NOT as `Violation` entries with non-zero count, so a `non-zero count` trigger is structurally foreclosed; right close is wontfix-by-construction.
3. **`DONE_WITH_CONCERNS` triage.** If a subagent reports `DONE_WITH_CONCERNS` and the concern is in-scope (perf regression on a solver task, unfixed lint, missing test), fix it before committing. For algorithm-phase work, include the BASELINE.md 20% regression budget as an explicit acceptance criterion in the subagent prompt.
4. **Module-deletion commits sweep stale doc-comments in production source.** When deleting a module, the verification `rg -n '<symbol>' backend/src/` often returns matches in unrelated model docstrings and seed comments. Fold those edits into the same commit; do NOT touch xfail `reason=` strings, alembic migration docstrings, or `CLAUDE.md`.
5. **Upstream-state check on tool-named P0 spikes.** When a P0 item names a specific external tool (Timefold, Choco, etc.), do a PyPI / GitHub status check before brainstorming integration. Archive status, Python-version compatibility, EOL signals can flip the outcome to "document and reject" (see ADR 0035).
6. **Bench-surfaced bug mid-run.** When a production-budget bench refresh exposes a new solver bug, the panic rows ARE legitimate refresh signal (`write_error_row` handles them gracefully). Let the bench finish, commit `BENCH_RESULTS.md` including panic rows, file a new OPEN_THINGS item for the bug, update dependent items' bodies to route through it. Do NOT stop the bench and rerun from scratch.
7. **Item bodies are hypotheses.** A P0 bug item's narrative names the SYMPTOM, not the CAUSE. Let the RED reproducer fail and follow the actual stack; phrase GREEN-phase tasks as "make the RED test go green", not "edit `<suspect_function>`".
8. **Smoke bench validates fixes; production refresh refreshes data.** The dev-loop smoke bench (~30s) suffices to validate a fix when the bug shape is "every cell panics" or "every cell emits a specific violation kind". The production refresh (wall-clock depends on `--jobs` and host; see `solver/CLAUDE.md` bench section) is for refreshing comparable artifacts in `BENCH_RESULTS.md`, not for proving a fix works. Run the production refresh in `run_in_background` and ship the PR on the smoke result.
9. **Integration-test xfail-removal items: gate on the integration-test flake-loop.** When an OPEN_THINGS item names an xfail removal as its deliverable, the gate is a 20-iteration flake-loop on the integration test at production wall-clock budget, NOT a bench-data narrative. Bench cells pin teachers (`_TEACHER_ASSIGNMENTS_*`); integration tests on the solver-driven path leave teachers null. A single-seed smoke bench feasible does NOT predict 20-iter flake-loop stability. Partial-close shape on flake-loop denial: ship the GREEN tests' xfail removals + the OPEN_THINGS update routing the remaining RED through an existing-axis item or a fresh item.
10. **Xfail-removal procedural shape: edit the test file first, then measure.** Apply all GREEN-branch edits (delete `@pytest.mark.xfail`, raise the in-test `solve_deadline_ms` to production budget, refresh the docstring) BEFORE running the flake-loop. GREEN: commit as-is. RED: `git checkout -- <test-file>` and reroute via the denial rule below.
11. **Flake-loop denial: reroute through an existing item when the failure axis matches.** When a flake-loop denial's failure shape's predicate + axis matches an already-open item's planned closure surface, reroute in one docs-only commit (rewrite the xfail item's body with the measurement; invert the dependency direction in the receiving item). Reroute applies ONLY when the failure axis matches; new mechanism on a NEW axis means file a fresh OPEN_THINGS item.
12. **Partial-improvement on the same axis: fresh item when mechanism shifts.** A partial fix closes one mechanism on an axis while a different mechanism on the SAME axis remains. Ship the partial fix in the closing PR; file a fresh OPEN_THINGS item for the residual mechanism. Test: "would the new item's body be substantively different from the closed one's?"
13. **Plan-time existence check on every test file the plan touches.** Before writing a plan task that says "extend `<path>.test.tsx`", `ls` it. Frontend mixes feature-local specs and `frontend/tests/`-level page tests. When the file is missing, say CREATE, name the canonical sibling to mirror, and account for stubbing sub-components the dialog mounts in EDIT mode. Same shape applies to production source files: a spec naming a target that doesn't exist may be implicitly proposing an extract-to-file refactor.
14. **Wait-until-done watcher on long-running bench: PID, not pgrep pattern.** When a long-running bench supervisor is `nohup`-detached and you want one notification on completion, capture its PID and watch with `until ! kill -0 "$PID" 2>/dev/null; do sleep 30; done`. Do NOT use `until ! pgrep -f '<supervisor command fragment>' >/dev/null; do ...` — the watcher's own bash command line embeds the pattern verbatim (via shell-snapshot eval expansion), so `pgrep -f` self-matches and the loop never exits even after the supervisor finishes. Same shape applies to any `pgrep -f` poll loop whose pattern names a sub-string of its own command line; the alternative `Monitor + log-tail` (per `solver/CLAUDE.md` bench rule) avoids the issue when you want streaming events rather than one-shot wait.
15. **Parallel-subagent pre-commit hook collision: stash the other agent's WIP, do not edit it.** When two subagents fan out on disjoint write scopes (one in `backend/`, one in `solver/solver-bench/`) and the first to commit has only its own files staged, the pre-commit `lint:rust` step still runs `cargo fmt --check` workspace-wide and surfaces the other agent's unstaged unformatted edits. The committing agent must NOT reformat the other agent's files (race on subsequent overlapping edits) and must NOT skip hooks. Pattern: `git stash push --keep-index -- <other-agent's-paths>` to park the WIP, commit, then `git stash pop` to restore. The parked agent's edits are byte-identical after pop; their commit lands cleanly on top because `cargo fmt` runs locally in their next iteration.
16. **Smoke bench is structurally weak for quality-predicate fixes.** Rule 8 names smoke as the validator when the bug shape is "every cell panics" or "every cell emits a specific violation kind". When the OPEN_THINGS item's failure shape is instead a quality-predicate miss (`worst_spread > N`, `home_room_miss > N`, `total_interior_gaps > N` from `solver-bench/src/quality.rs`), the 5s smoke does NOT predict the production-budget result; the LAHC search needs full wall-clock to traverse the smooth-axis gradient on a dreizuegig-sized fixture. Concrete example: a `class_day_balance` weight bump that left smoke `worst_spread_med = 4` (over the bar) on dreizuegig pinned at 5s still cleared the 5000 ms `test_grundschule_schedule_meets_quality_bar` flake-loop 20/20. Gate quality-predicate fixes on the production-deadline integration-test flake-loop (rule 9) directly; do NOT escalate the fix's magnitude on the smoke gate alone.
17. **Plan-time surface check on every HTTP path and direct-ORM seed in a tenancy-test plan.** Rule 13 covers test FILES; API paths and direct-ORM seeds need the same audit. Before writing a plan task that POSTs `/api/<path>`, `rg -n '@router\.(post|patch|delete|get)' backend/src/klassenzeit_backend/scheduling/routes/<aggregate>.py` for the actual handler shape: the placement API surfaces as `PATCH /placements/<lesson_id>/<time_block_id>` for move, `PATCH .../pin`, `POST /swap`, NOT a `POST /placements`, so a tenancy test that POSTs `/api/placements` 405s before the cross-school assertion can run. Before writing a seed that constructs an aggregate via direct `<Aggregate>(...)` (bypassing factories), audit NOT NULL columns on that model: `rg -n 'nullable=False' backend/src/klassenzeit_backend/db/models/<aggregate>.py`. Omitting a NOT NULL FK (`ScheduledLesson(teacher_id=None, ...)`, `ScheduledLesson(room_id=None, ...)`) fails the DB constraint before the tenancy assertion runs. Same audit shape applies to helper function names the plan references: `rg -n '^async def <name>\|^def <name>' backend/src/klassenzeit_backend/scheduling/<module>.py` before naming a target. A plan that names a fictional symbol (e.g. `persist_placements` vs the real `persist_solution_for_class` / `persist_solution_for_all_classes`) costs a spec-reviewer round-trip and leaks the bad identifier into subagent prompts.
